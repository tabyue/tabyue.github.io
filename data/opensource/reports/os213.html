Harness 讨论里被忽略的那一层

具身 Agent 的论文与演示大多假设「Agent 能直接调用机器人的能力」。但真到 ROS 2 系统上，这句话要解决一堆具体问题：

  • 能力散落在话题（topic）、服务（service）、Action、参数服务器里，没有统一的工具描述；
  • 观测是相机图像、点云、关节状态，不是 LLM 能直接吃下的格式；
  • 任务要能被打断、澄清、接管，需要对话与任务上下文管理。

RAI 是一个厂商中立（vendor agnostic）的 agentic 框架，专门做这层适配。

为什么这层值得单独存在

RoboHarness（arXiv 2610.14018）证明了接口设计能决定成败：不训练任何模型，只给 LLM 一套视觉—几何控制面板，Qwen3.8-Flash-Next 在 BEHAVIOR Challenge 2025 上就超过了最强 VLA。

但 RoboHarness 的实现绑定特定本体。RAI 的价值在于厂商中立——同一套 Agent 逻辑可以换不同机器人跑。

适用方向

  • 已经在 ROS 2 上有机器人、想快速接入大模型 Agent 做任务编排与交互的团队；
  • 多本体并存、希望 Agent 逻辑复用的场景；
  • 想研究「Agent 该调用哪些粒度能力」的团队——框架能让你快速换工具粒度做对照实验。

三个核心职责

  1. 能力包装：把 ROS 2 的各类接口包装成 Agent 可调用、带自然语言描述的工具。关键是描述要写得让模型知道「什么时候该用」，而不只是「怎么调」。
  2. 观测适配：把相机图像、点云、机器人状态转成多模态模型能消化的格式。点云尤其麻烦——直接塞进 LLM 没有意义，通常需要先降维或投影成图像。
  3. 上下文管理：维护对话与任务上下文，支持人机交互中的澄清与接管。这一条在真实部署里比前两条更容易被低估。

概念性接入骨架

from rai import RAIAgent, ROS2Connector

connector = ROS2Connector()

# 1. 把 ROS 2 接口声明为工具（描述写给模型看，不是写给人看）
connector.register_tool(
    name="move_arm_to_pose",
    ros_type="action",
    target="/arm_controller/follow_joint_trajectory",
    description="把机械臂末端移动到指定位姿。用于需要精确放置的场景，"
                "不适合需要力控的接触式任务。",
)

# 2. 声明观测源
connector.register_observation(name="head_camera", ros_topic="/camera/color/image_raw")
connector.register_observation(name="joint_states", ros_topic="/joint_states")

# 3. 起 Agent
agent = RAIAgent(connector=connector, model="gpt-6-luna")
agent.run(task="把桌上的红色杯子放到托盘里")

接入自己的机器人

  1. 列出机器人暴露的所有 ROS 2 接口，挑出真正需要给 Agent 的那部分；
  2. 为每个工具写「什么时候该用」的自然语言描述——这一步决定调用成功率；
  3. 确认观测格式（图像编码、点云降采样策略）；
  4. 先在仿真里跑通，再上真机。

收益来源

RAI 这类框架的价值不在「提升某个基准分数」，而在降低多本体接入成本：

  • Agent 逻辑一次写、多本体复用；
  • 工具粒度可以快速调整做对照实验；
  • 与 ROS 2 生态的既有资产（导航、MoveIt、各类驱动）直接打通。

成本

  • 多一层适配会引入延迟，高频控制回路不适合走 Agent；
  • 工具描述的质量直接决定调用成功率，这部分是人工成本；
  • 观测适配（尤其点云）需要根据任务定制，不是开箱即用。

选型建议

  • 已有 ROS 2 机器人、想接大模型：RAI 是最直接的选择。
  • 想验证「harness 能不能超过 VLA」：看 RoboHarness，它的结论更激进。
  • 需要 1 kHz 级运控：不要走 Agent 层，这一层只适合任务编排与秒级决策。

高频坑

  • 工具描述只写参数、不写适用场景：模型会乱调。描述里必须写「什么时候不该用」。
  • 把高频控制塞进 Agent：规划与运控要分层，Agent 只负责编排。
  • 点云直接喂模型：先降采样或投影成图像，否则既浪费 token 又没有效果。
