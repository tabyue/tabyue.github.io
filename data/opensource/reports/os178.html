要解决的问题：VLA 没有短期记忆

绝大多数 VLA 在每一步都只看当前帧。在闭环控制里这会带来一个非常具体的失败模式：当不同位姿投影出相似图像（感知走样，perceptual aliasing）时，策略无法判断自己刚刚是从哪个方向过来的，于是会在两个位姿之间反复横跳。这种振荡不一定导致任务失败，但会显著拉长节拍、增加机械磨损，是真机部署中最伤用户体验的问题之一。

REKI 的做法是把记忆做成动作专家内部的一组 token，而不是外接一个记忆网络或额外引入历史帧。

整体结构

观测（2 路 256x256 相机） + 文本指令
        │
        ▼
  VLM 骨干（Qwen 系列，约 2.2B）
        │  编码 prompt 与各帧视角
        ▼
  动作专家（约 0.2B，flow matching）
        │
   [ register x32 ][ action tokens ]
        │      │            │
        │      └── 对更早帧 register 做自注意力  ← 记忆通道
        └───────── 对 VLM 编码结果做交叉注意力
        ▼
   动作块（action chunk）

为什么它可以「几乎免费」

关键在于把 register 定义成 $r_t = f(o_t)$，即只依赖观测。如果 register 依赖动作，它就会随策略输出变化，跨步无法复用。论文显式做了这个约束，于是第 $t$ 帧的 register 在后续所有引用该帧的步骤里都是常数，可以放进滚动窗口缓存。

公开数据路线的意义

REKI 全部在公开数据上预训练，数据配方覆盖三类：公开机器人数据、第一人称人类数据、视觉语言数据。它证明了在规模不占优的情况下，数据配比 + 简单架构足以打到接近两倍规模模型的位置。对小团队而言这是最友好的一条路径。

记忆通道的三条注意力路径

路径 作用
register → VLM 编码结果（交叉注意力） 把当前帧的视觉语言信息压缩进 register
register_t → register_{t-K..t-1}（自注意力） 跨帧记忆，构成短期历史
action tokens → register（同序列内） 动作生成时读取记忆

条件注入

机器人状态 $s$ 与 flow 时间步 $\epsilon$ 通过 adaptive RMSNorm 注入：

$$\mathrm{AdaRMSNorm}(x; s, \epsilon) = \gamma(s, \epsilon) \odot \frac{x}{\mathrm{RMS}(x)} + \beta(s, \epsilon)$$

每种机器人状态配置（不同本体的状态维度与量纲）配一个独立的小状态 MLP，这让同一个动作专家骨架能适配多种本体，而不必为每种本体重新设计输入层。

动作生成

动作专家用 flow matching 生成动作块，而非自回归离散 token。对连续控制而言，flow matching 避免了动作离散化带来的量化误差，也天然支持一次输出多步动作块。

简化伪代码

"""
REKI 风格：在动作专家前插入跨帧 register。
"""
class ActionExpertWithMemory(nn.Module):
    def __init__(self, dim, n_reg=32, win=8):
        super().__init__()
        self.reg = nn.Parameter(torch.randn(n_reg, dim))
        self.cross_attn = CrossAttn(dim)
        self.self_attn = SelfAttn(dim)
        self.cache = deque(maxlen=win)
        self.flow_head = FlowHead(dim)

    def encode_frame(self, vlm_feat):
        # vlm_feat: VLM 编码后的 prompt + 各帧视角
        q = self.reg.expand(vlm_feat.size(0), -1, -1)
        r = self.cross_attn(q, vlm_feat)   # 只依赖观测
        self.cache.append(r.detach())       # 因此可缓存
        return r

    def forward(self, vlm_feat, state, tau):
        r_t = self.encode_frame(vlm_feat)
        hist = torch.stack(list(self.cache)[:-1], dim=0)
        r_mem = self.self_attn(r_t, hist) if len(hist) else r_t
        x = self.adaptive_rmsnorm(state, tau)
        return self.flow_head(torch.cat([r_mem, x], dim=-1))

推理（概念流程）

  1. 用 VLM 骨干编码文本指令与各相机视角；
  2. 动作专家对最近的 $K$ 帧计算并缓存 register；
  3. 以当前本体状态与 flow 时间步为条件，去噪生成动作块；
  4. 执行动作块的前若干步，回到第 1 步（滚动窗口只保留最近 $K$ 帧的 register）。

在自己本体上微调的要点

  • 保持 register 只依赖观测这一约束；一旦让它依赖动作，缓存就失效，显存与耗时都会上升；
  • 每种状态配置用独立的小状态 MLP，不要把所有本体的状态拼成一个大向量；
  • 微调数据可以与预训练配方不一致，但建议保留第一人称人类数据与视觉语言数据的一定比例，防止表征退化。

"""

def oscillation_rate(traj):
    # 相邻动作方向反转的次数占比
    d = np.diff(traj, axis=0)
    rev = np.sum((d[1:] * d[:-1]).sum(-1) < 0)
    return rev / max(len(d) - 1, 1)

如何看待这个成绩

REKI 的定位是研究基线 + 工作站级部署，不是端侧实时方案。21.8 ms 是在 H100 上测的；换算到 Jetson 级算力，0.2B 的动作专家仍可实时，但 2.2B 的 VLM 骨干会成为主要开销。若目标是边缘部署，需要自己做量化验证，官方暂未发布量化权重。

另一个诚实的边界是：在部分分布外基准上它仍被约两倍规模的模型超过，说明参数量的天花板依然存在，记忆补的是振荡问题而不是能力上限。

REKI 的独特位置

  1. 记忆放在动作专家而不是视觉骨干。 记忆的是「专家已消化的信息」，而不是仍需再加工的图像特征——这是它便宜的根本原因。
  2. 完全开源到数据整理与部署环节。 大多数 VLA 只放权重与训练代码，评测与部署脚本往往缺失，而这两块恰恰是第三方复现的瓶颈。
  3. 只用公开数据预训练。 对无法拿到大规模真机数据的团队，这是唯一可走的路线，而 REKI 证明了这条路的上限比预想的高。

与同类记忆方案的差别

MemoryVLA 类方法通常引入独立的记忆模块或额外的历史帧编码，参数与计算开销随记忆长度增长；REKI 的 register 数量固定为 32、且可缓存，记忆长度的成本是常数级。
