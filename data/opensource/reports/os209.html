动作视界的困境

VLA 输出动作块 $\mathbf{a}_{t:t+H}$，实际执行时常采用滚动视界：每执行 $h$ 步（$h < H$）就重新推理一次。

$H$ 与 $h$ 的取值是个两难：

参数 取大 取小
$H$（预测长度） 动作连贯、抖动小，但后段预测易过时 响应快，但动作抖动、缺乏连贯
$h$（执行步长） 推理次数少、成本低，但环境变化响应慢 响应快，但推理频率高、延迟敏感

真实任务里最优值是随阶段变化的：接近物体阶段希望连贯（大 $H$、大 $h$），精细对位阶段希望高频校正（小 $h$）。

VLA-Corrector 的做法

不改训练，不改主体，加一个轻量头：

  1. Detect：对当前动作块 $\mathbf{a}_{t:t+H}$ 的每一段（或每一步）估计一个可信度；
  2. Correct：对低可信度的部分做局部修正；
  3. Execute：按修正后的块执行，有效视界由数据决定而不是由超参决定。

关键收益是把「$h$ 设多少」这个拍脑袋的超参，变成模型自己判断的事。

适用边界

  • 适合：已经部署了基于动作块的 VLA（$\pi_0$ 系列、SmolVLA、LeRobot 生态），想在推理侧提效果；
  • 不适合：不输出动作块的单步策略——这类策略本来就没有视界问题。

数据流

观测 o_t
    ↓
VLA 主干（冻结或轻量微调）
    ├──→ 动作块 a_{t:t+H}
    └──→ 中间表征 h_t
              ↓
        Detect Head（轻量）
              ↓
        每步可信度 c_{t}, ..., c_{t+H-1}
              ↓
        Correct Head（轻量）
              ↓
        修正后的动作块 ã_{t:t+H}
              ↓
        执行前 k 步（k 由可信度决定），重新推理

两个头为什么可以很轻

它们读的是 VLA 已有的中间表征 $h_t$，而不是重新编码观测。因此额外参数量极小，额外计算量也主要是一次小 MLP 的前向。

这与本站已收录的 Backtrack（arXiv 2610.32941）思路同源：VLA 的内部表征里其实已经包含了「这一步靠不靠谱」的信息，只是没有被显式读出来。

为什么叫「自适应动作视界」

传统滚动视界用固定 $h$。VLA-Corrector 让实际执行步数由可信度决定：

$$ k = \max { j : c_{t+j} > \tau } $$

可信度高就多执行几步（省推理），可信度掉下来就早点重算（保准确）。

挂载到已有 VLA

from vla_corrector import DetectCorrectHead
from lerobot import load_policy

policy = load_policy("smolvla")            # 你的冻结 VLA
head = DetectCorrectHead(policy.hidden_size, horizon=policy.action_horizon)

# 推理循环
obs = env.reset()
while not done:
    actions, hidden = policy.forward_with_hidden(obs)   # 拿到中间表征
    corrected, conf = head(actions, hidden)             # 检测 + 纠正
    k = int((conf > 0.7).sum())                         # 按可信度决定执行步数
    for a in corrected[:max(k, 1)]:
        obs, done = env.step(a)

落地建议

  • 先只开 detect，不开 correct：看可信度曲线的形状是否合理（接近阶段高、接触阶段低），再决定是否启用纠正；
  • 阈值 tau 要在真机上调：仿真里的可信度分布通常比真机更集中，直接搬阈值会误判；
  • 与 chuncked 推理基础设施配合：本站 ai-infra 模块的「Chunked VLA 推理基础设施」一节讲的是同一问题的系统侧视角，可以对照阅读。

收益来源

这个方法的收益有两部分，部署时应分别衡量：

  1. 准确率收益：低可信段被纠正，减少「拿着过时预测硬执行」导致的失败；
  2. 效率收益：高可信段可以多执行几步，降低推理频率——在端侧部署时这部分往往比准确率更值钱。

需要注意

  • 可信度是模型自己估的，需要验证它是否与真实执行成败相关（画校准曲线）。若两者无关，自适应视界就失去了依据；
  • 纠正头如果训练不当，可能引入新的抖动——应对比「纠正后 vs 不纠正」的 jerk 指标。

选型建议

  • 已部署动作块 VLA、想低成本提效：VLA-Corrector 是最轻的切入点；
  • 长程失败多、需要恢复：看 Backtrack；
  • 端侧延迟是硬约束：考虑一步生成策略（但要承担重训成本）；
  • 系统层面块间停顿明显：看 Chunked 推理基础设施的方案。

这几条路线并不互斥，实际部署常组合使用。
