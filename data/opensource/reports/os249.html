workbench-mobile-home-robot 是一个面向轮式家庭机器人的 evidence-first runtime：动作受限（bounded actions）、事件可重放（replayable events）、校验失败即闭合（fail-closed verification）。技术栈覆盖 ROS 2、MoveIt 2、Gazebo、SocketCAN 与任务规划，并把 world-model 纳入运行时。

仓库 Python / Apache-2.0，2026-11-06 活跃推送，约 265 star，创建于 2026-08-04。

为什么值得关注：家庭机器人最难的不是「能不能做」，而是「做错了能不能查、能不能安全停下」。把可重放事件与 fail-closed 校验做进运行时，等于把可观测性和安全边界放到架构层，而不是指望上层策略自觉。这与本站 platform-engineering 模块讲的评测基础设施、mobile-robot-navigation 模块讲的地图与代价层可以直接对读。

  1. bounded actions：动作空间被显式限定，策略不能任意下发未声明的动作；
  2. replayable events：所有关键事件带可重放记录，事后能精确复现当时的状态与决策；
  3. fail-closed verification：任一前置校验不通过即拒绝执行，默认状态是「不动」而不是「先做再说」；
  4. ROS 2 / MoveIt 2 / Gazebo / SocketCAN：标准的机器人软件栈，便于替换本体与执行器；
  5. 任务规划 + world-model：运行时内维护任务状态与对环境的预测，用于校验动作后果；
  6. 证据层：把「为什么允许这一步」写成可检查的证据，而不是散落在日志里的字符串。

分层的要点是：校验在动作下发之前，证据在动作执行之后，二者构成闭环。

# 伪代码：fail-closed 的动作下发路径
def dispatch(runtime, action, evidence_store):
    if action.kind not in runtime.allowed_actions:
        return runtime.refuse('action not in whitelist')
    checks = runtime.verify(action)          # 世界模型预测 + 状态 + 权限
    if not all(checks.values()):
        return runtime.refuse(checks)        # 默认不动
    receipt = runtime.execute(action)
    evidence_store.append(receipt, checks)   # 可重放证据
    return receipt

建议按运行时而非按任务评估：

层 指标
安全性 未授权动作拦截率、校验失败时的默认行为是否确实是「不动」
可观测性 事件重放能否复现失败、证据字段是否足以定位根因
实时性 校验链路引入的额外延迟、动作频率上限
可移植性 换本体 / 换执行器需要改几处配置
