项目概述

OpenWAM 是斯坦福大学团队开源的可组合式世界-动作模型（World-Action Model, WAM）框架，论文 OpenWAM: An Open Framework for Composable World-Action Models 的官方代码。

项 内容
组织 Stanford University（项目主页 openwam.stanford.edu）
许可 AGPL-3.0
语言 Python
创建 2026-06-08，持续更新中
适配基准 LIBERO、RoboTwin、CALVIN、LeRobot

它解决的是 WAM 研究的「工程碎片化」问题。 世界-动作模型这条路线这两年论文不少，但每篇都是自己的一套代码：视频预训练一份、动作策略一份、动力学一份，彼此不兼容，导致「换个基座再跑一遍」的成本高到没人做。OpenWAM 把这三块整合进一个统一流程，并做成可组合的——各模块可以单独替换。

为什么这件事重要

WAM 的核心假设是：先学会预测世界会怎么变，再把动作接上去。听起来简单，但三个子模块的接口从来没有标准化：

视频预训练  ──►  ?  ──►  动作策略  ──►  ?  ──►  执行
                              ▲
                         正/逆动力学

中间的「?」就是各家自己写的胶水代码。OpenWAM 填的就是这两个问号。

三件套：因果视频预训练 + 动作策略 + 正逆动力学

┌─────────────────────────────────────────────────────┐
│  1. 因果机器人视频预训练（无动作标签）                   │
│     输入：历史视频帧序列                                │
│     输出：未来帧 / 未来隐变量预测                        │
└──────────────────────┬──────────────────────────────┘
                       │  共享表征
        ┌──────────────┴──────────────┐
        ▼                             ▼
┌───────────────┐           ┌──────────────────┐
│ 2. 动作策略    │           │ 3. 正/逆动力学     │
│  观测 → 动作块 │           │  正：状态+动作→下一状态│
│               │           │  逆：状态+目标→动作  │
└───────────────┘           └──────────────────┘

因果（causal） 是这里的关键词：预训练阶段只允许模型看过去来预测未来，不能看未来帧。这个约束的重要性在 Long-WAM（p194） 里被量化证明了——换成双向预训练的基座，加长上下文几乎没有收益。

可配置的交互模式

框架支持多种模块间交互方式，不是写死一条路：

模式 含义 适用
联合去噪 视频与动作在同一个去噪过程里联合生成 两者强耦合的任务
先视频后动作 先预测未来视频隐变量，再据此生成动作 需要显式「想象结果」的任务
共享架构 视频与动作共用一个主干 参数受限时
双专家模型 视频专家 + 动作专家各自独立，通过接口通信 想单独升级某一侧时

双专家模式对工程团队最实用：视频基座和动作头可以各自迭代、各自换版本，接口不变。

扩展 SDK

框架提供扩展点，可接入：

  • 自定义策略（policy）
  • 自定义动作解码器（action decoder）
  • 自定义仿真环境（environment）

这意味着不必改用它的模型也能用它的流水线。

快速上手

git clone https://github.com/OpenWAM/OpenWAM
cd OpenWAM
pip install -r requirements.txt

建议的验证顺序：

  1. 先跑一个已适配基准的最小实验。LIBERO 或 CALVIN 二选一，确认整条流水线能跑通。不要一上来就接自己的数据。

  2. 确认因果掩码真的开着。这是最容易出错也最难查的一处：框架默认可能为了调试方便打开双向注意力，一旦忘了关，你的「加长历史无收益」会与 Long-WAM 的发现完全相反，而且查不出来。

  3. 对比两种交互模式。用同一份数据跑「联合去噪」与「先视频后动作」，看哪个在你的任务上更好。这个对比的成本很低，但结论对后续路线选择影响很大。

  4. 再接入自己的本体。走扩展 SDK 的 policy / action decoder / environment 三个扩展点，不要改框架核心代码——AGPL-3.0 下改动核心意味着你也要开源。

许可提醒

AGPL-3.0 是这份清单里最严格的许可。与 MIT（SPEAR）或 Apache-2.0 不同，AGPL 的传染性延伸到网络服务——如果你把基于 OpenWAM 的东西作为服务对外提供，按 AGPL 的要求也需要开放源码。

商业闭源场景请务必先过一遍法务：要么改用别的框架，要么与斯坦福方谈商业授权。

与本站相关条目的关系

与 Long-WAM（p194）：Long-WAM 回答的是「WAM 该用多长的历史、基座该怎么预训练」，OpenWAM 提供的是「把这套东西搭起来的框架」。一个给结论，一个给工具。想在 OpenWAM 上验证 Long-WAM 的结论是很自然的组合。

与 WareFly-VLA（p189）：WareFly 的结论之一是跨具身迁移需要动力学对齐。OpenWAM 内置的正/逆动力学模块正是做这件事的地方——正动力学给出「这个动作在这个本体上会怎样」，逆动力学给出「要达成这个状态该出什么动作」。两者正好对上。

与 WBC-AGILE（os142）：AGILE 是 NVIDIA 的人形全身移动操作工作流，偏工程落地与 sim-to-real；OpenWAM 偏世界模型研究。目标不同，可互为参照。
