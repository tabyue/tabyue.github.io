项目概述

LingBot-World 2.0（又名 LingBot-World-Infinity）是蚂蚁灵波科技 2026-07-08 开源的第二代交互式世界模型，是 os091 LingBot-World 的重大迭代。

它要解决的核心痛点只有一个：交互式世界模型「生成越久越崩」。

第一代及同期同类工作普遍存在同一个问题——自回归地一段段生成视频，误差会沿时间累积：十几秒还像样，一分钟后画面漂移、物体消失、场景失去一致性。这让世界模型只能做 demo，做不了「可以一直玩下去」的交互环境，更谈不上给具身策略当训练场。

2.0 的答案是因果预训练范式 + 逐 chunk KV 缓存推理，把「任意长交互下输出质量保持一致」作为第一目标。

技术报告：arXiv:2607.07534《Infinite Worlds with Versatile Interactions》

架构与四大升级

代码库基于 Wan2.2 视频生成栈构建，generate.py 用 KV 缓存做因果推理、逐 chunk 处理视频帧而非一次性全出——这是「无限时长」在工程上的落点。

① 无界交互时长（因果预训练范式）

传统双向 / 全序列生成：
  一次性看到整段时序 → 长度受限于窗口 → 超出窗口就断裂

2.0 因果范式：
  chunk_1 → KV cache → chunk_2 → KV cache → chunk_3 → ...
  每个 chunk 只依赖历史，训练时就按因果方式预训练
  → 推理长度不再受训练窗口硬约束，质量随时长保持稳定

关键不在于「推理时改成因果」，而在于预训练阶段就按因果目标训练——否则推理阶段的因果约束与训练分布不匹配，长程漂移依旧会出现。

② 实时响应（蒸馏变体）

从基座蒸馏出实时变体，足以驱动 720p / 60fps 视频流。这个指标意味着世界模型第一次进入「可交互游戏级」帧率区间，而不是离线渲染。

③ 高度多样的交互元素

动作谱系大幅扩展（攻击 / 射箭 / 施法 / 射击等），并支持更丰富的文本驱动事件——不只是控制角色移动，还能用语言在世界里「制造事情发生」。

④ Agentic Harness（世界建模领域首创）

2.0 首次把智能体框架引入世界模型，用两个 agent 分工：

Agent 职责
pilot agent 规划并执行角色行为——相当于「玩家」
director agent 随场景推进合成新的环境元素——相当于「导演 / DM」

为什么这件事重要：过去世界模型是被动的——你给动作，它出画面。有了 director agent，世界会主动演进：新的敌人、新的场景元素随剧情出现。对具身研究的意义是，它开始具备「自动生成课程（curriculum）」的雏形，而不只是一个回放器。

快速开始

git clone https://github.com/robbyant/lingbot-world-v2.git
cd lingbot-world-v2

pip install -r requirements.txt

# 权重（HuggingFace 或 ModelScope 任选其一）
huggingface-cli download robbyant/LingBot-World-Infinity-14B-causal-fast \
    --local-dir ./checkpoints/lbw2-14b-causal-fast

生成：逐 chunk 因果推理

python generate.py \
    --ckpt ./checkpoints/lbw2-14b-causal-fast \
    --prompt 'a knight walking through a misty forest' \
    --chunk_size 16 \
    --num_chunks 60          # 想跑多久就加多少 chunk

generate.py 的关键行为：

  • KV 缓存跨 chunk 复用 —— 历史不重算，显存换时间
  • 逐 chunk 出帧 —— 可以边生成边看，而不是等全部算完
  • 想验证「无限时长」是否成立，把 num_chunks 调大后对比首尾画质与场景一致性，这是最直接的验证方式

接入 Agentic Harness

pilot agent    → 输出角色动作序列（走 / 攻击 / 施法 ...）
director agent → 输出环境事件（生成新元素 / 推进剧情）
              ↓
        世界模型逐 chunk 渲染

实践建议：先固定 director、只调 pilot，确认动作可控性；再放开 director，否则两个 agent 同时变动很难定位问题来源。

显存与吞吐注意

  • 14B + 长交互场景，KV 缓存会持续增长，长跑要留出余量或启用缓存裁剪
  • 实时变体（720p/60fps）与基座是不同权重，别拿基座去追帧率指标
