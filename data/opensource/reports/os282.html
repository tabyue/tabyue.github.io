读法：重点看慢层的触发条件——如果 System 2 每次都被调用，架构就退化成普通的大模型 Agent，端侧与延迟优势全失；如果几乎不触发，自我纠正又可能形同虚设。触发频率与纠正幅度这两个旋钮，才是判断它是不是真的「System 1 优先」的地方。另一个要盯的是在线可塑性的稳定性：局部学习规则最容易出的问题是灾难性遗忘，演示里看不出，长跑才看得见。

class Probe:
    def __init__(self):
        self.n_fast = 0
        self.n_slow = 0

    def step(self, obs, agent):
        self.n_fast += 1
        act = agent.system1(obs)
        if agent.needs_correction(obs, act):
            self.n_slow += 1
            act = agent.system2_revise(obs, act)
        return act

    def ratio(self):
        return self.n_slow / max(self.n_fast, 1)

对在线学习架构类项目，该核对的是四项而非跑分：

  1. 慢层调用频率：System 2 触发占比是否真的稀疏，这是「System 1 优先」是否成立的唯一硬判据；
  2. 长时稳定性：连续适应下早期能力是否被覆盖（灾难性遗忘），需要长跑而非 demo；
  3. 离线可用性：断掉外部模型调用后 System 1 回路是否完整，延迟是否落在控制环预算内；
  4. 纠正有效性：System 2 触发后错误率是否真的下降，而不是只多消耗了算力。
