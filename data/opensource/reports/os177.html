从画图到控机器人

Black Forest Labs 以 FLUX 图像生成模型闻名。它做机器人控制的逻辑是：视频生成模型在海量互联网视频上预训练后，已经隐式学到了物体如何下落、碰撞、被推动——这正是机器人规划需要的物理先验。

FLUX 3 Action 把这个先验接到机器人上：不做纯 VLA 的「观测 → 动作」映射，而是同时预测未来视频帧和动作，两者在同一个去噪过程里联合生成。这样动作预测就被「未来会变成什么样」这个任务约束住了。

为什么联合去噪有用

纯 VLA 的鲁棒性上界主要受数据覆盖率限制：没见过的状态就不知道怎么动。而未来观测预测可以从无动作标签的海量视频中学习，这部分监督不需要机器人数据。FLUX 3 Action 正是把图像/视频预训练的红利搬到控制上。

代价与对策

联合去噪比纯动作头慢得多。BFL 的对策是给出步数蒸馏（1 步）与FP8r 量化包，把推理成本压到可部署区间。这实际上是承认了 WAM 的部署成本问题，并用蒸馏而非架构改动来解决——与学术界的表征蒸馏思路不谋而合。

def predict(frames, state, instruction, steps=4):
    z_v = noise_like(future_video_shape)   # 未来视频的潜变量
    z_a = noise_like(action_chunk_shape)   # 动作块的潜变量
    cond = encode(frames, state, instruction)

    return decode_action(z_a), decode_video(z_v)

如何看待这个结果

「7B 打过更大的开源模型」说明的是视频预训练底座的迁移效率，而不是 WAM 范式一定优于 VLA。WAM 的推理成本仍显著高于 VLA（参见同类工作中 14B WAM 单次推理 3 秒 / 45.9 GB 的报道），这也是 BFL 提供 1 步蒸馏与 FP8r 包的原因。

对工程团队的现实建议是：先看部署预算再选范式——如果控制回路允许百毫秒级延迟且有足够显存，WAM 值得一试；如果只有 32 ms / 消费级卡的预算，VLA + 表征蒸馏可能是更实际的路线。

FLUX 3 Action 的独特位置是：它是少数把工业级视频生成底座真正开放出来的 WAM，且许可宽松（Apache-2.0）、生态对接成熟（LeRobot）。
