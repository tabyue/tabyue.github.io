为什么 VLA 需要 RL 后训练

监督微调（SFT）有一个结构性上限：它只能学到示教数据里出现过的动作分布。示教再干净，也覆盖不到「物体被碰歪了怎么办」「抓取滑了一半怎么救」这类分布外情形。RL 后训练的价值就在这里——让策略在自己会犯错的分布上被优化。

但 VLA + RL 的工程复杂度比 LLM + RL 高一个量级：

  • 环境不是纯文本的，需要物理仿真或真机；
  • rollout 慢，一次交互几十到几百毫秒；
  • 奖励稀疏，多数任务只有末端成功信号；
  • 模型输出的是连续动作块（action chunk），不是离散 token。

VLARLKit 的作用就是把这四件事的常用解法固化下来。

它补的是哪一层

   你的 VLA 模型            ← 你自己的
   ─────────────────────────────
   VLARLKit                 ← 这一层
     ├ 环境封装（sim / real）
     ├ rollout 收集与缓存
     ├ 奖励与优势估计
     └ 策略更新循环
   ─────────────────────────────
   LIBERO / 自定义基准       ← 评测

分层结构

层 职责 关键设计
环境层 封装仿真 / 真机 统一 observe / act 接口，屏蔽本体差异
采集层 并行 rollout 多环境并行 + 轨迹缓存，缓解交互慢
学习层 优势估计与更新 面向 action chunk 的优势分配
模型层 VLA 骨干 可替换，只需满足动作头接口

与通用 RL 库的差别

通用 RL 库（Stable-Baselines3 之类）假设策略是一个小 MLP，输入是低维状态。VLA 的输入是图像 + 语言，输出是动作块，参数量在 B 级。这带来两个必须专门处理的问题：

  1. 显存：策略前向 + 反向都要过 VLM 骨干，单卡放不下 rollout 批量；
  2. 动作块的优势分配：一次决策产出 $H$ 步动作，奖励是逐步给的，需要决定优势怎么在这 $H$ 步上摊。

VLARLKit 的价值主要就在这两点上。

  • AgenticRoboRL: Bringing Coding-Agent Post-Training to Agentic Robotics — 与 VLARLKit 形成上下层互补：一个训规划器，一个训 VLA。
  • DONIC: Generalist Dexterous Bimanual Tracking Control — PPO + BC 回收成功 rollout 的实践范本，其中的 Clip-Centered Advantages 思路可直接借到 VLA-RL。
  • Agentic World Action Models — 把代码流引入 WAM，代表另一条「让模型更强」的路线。

最小流程

from vlarlkit import Trainer, make_env

# 1. 环境：仿真基准
env = make_env('libero/spatial', n_envs=8)

# 2. 载入你 SFT 好的 VLA
policy = load_vla('checkpoints/my_vla_sft')

# 3. 配置 RL
trainer = Trainer(
    policy=policy,
    env=env,
    algo='ppo',
    horizon=8,            # action chunk 长度
    rollout_steps=2048,
)

# 4. 训练
trainer.train(total_steps=1_000_000)

建议的验证顺序

  1. 先跑通 SFT 基线的评测，记下成功率——这是 RL 的起点；
  2. 只开 rollout 不更新，确认采集链路与显存没问题；
  3. 用稠密一点的奖励先跑一小段，确认成功率真的在涨；
  4. 再换成稀疏的末端奖励跑完整实验。

跳过第 3 步是最常见的失败原因：奖励太稀疏时，早期曲线看起来完全没在学，很难区分是 bug 还是正常。

这是一个库而非模型仓库，因此没有官方榜单成绩。它的价值在于把 VLA-RL 这条链路的工程成本从「几周」压到「几天」。

与相关项目的分工

  • 与 RLinf（RLinf/RLinf）相比：RLinf 是面向具身与 agentic AI 的大规模 RL 基础设施，更重；VLARLKit 更轻，聚焦 VLA 这一层。
  • 与 AgenticRoboRL（arXiv:2610.28589，见本期论文 p264）相比：后者训练的是规划器，VLARLKit 训练的是底层 VLA 策略，两者正好可以叠起来用。
项目 定位 训练对象 适合谁
VLARLKit VLA-RL 库 VLA 策略本身 已有 SFT VLA、想上 RL 的团队
RLinf 大规模 RL 基础设施 策略 + 系统 需要分布式大规模训练
AgenticRoboRL 规划器后训练框架 上层规划器 用 LLM 做规划的系统
hflow 训练数据质量验证 SDK 数据 想先看数据有没有问题的团队

选型建议：如果你的失败模式是「示教覆盖不到的情形会挂」，用 VLARLKit；如果是「任务分解错了」，用 AgenticRoboRL 那类规划器后训练；如果是「数据本身有脏样本」，先看 hflow。
