bjkim95/rofacto 是 CoRL 2026 论文 Robot-Factored World Models via Robot Rendering 的官方实现，约 32 star（2026-11-21 核验），Apache-2.0 许可，Python，2026-06-25 创建、11-10 更新，配有项目主页。

它切的是世界模型里一个常被忽略的混淆项：机器人自己也在画面里。当策略用相机观测训练世界模型时，观测变化同时来自「环境 / 物体在动」和「机器人本体在动」，单体模型必须把两者一起解释，参数被大量花在拟合本体运动这种与任务无关的规律上。rofacto 用可微的机器人渲染（robot rendering）把本体对观测的贡献显式建模并从场景中因子化出来，让世界模型专注预测环境与物体的演化。

值得单独收录，是因为它和本轮 p397 MoRE 正好给出两种正交的分解维度：MoRE 在模型内部按刚体 / 可变形 / 可抓握的物理机制分专家，rofacto 在建模对象上把「机器人」与「世界」分开。两者可以叠加，也提示 /learn/world-models-llm 与 /learn/computer-vision 的读者：世界模型该以什么为条件，本身就是设计决策而不是默认设定。

按论文标题、项目主页与仓库定位，可归纳为四个部分（注意：结构性归纳，具体网络结构、渲染器与损失权重以论文与 README 为准）：

  1. 可微机器人渲染器：给定本体状态（关节角、位姿）与已知几何 / URDF，渲染出机器人在当前视角下应出现的像素或特征，作为「本体贡献」的估计。可微是关键——它需要把梯度从世界模型传回本体状态与渲染参数。
  2. 因子化表征：把观测拆成本体相关分量与场景相关分量，世界模型只在后者上做未来预测，避免用容量去记机器人自己的运动规律。
  3. 场景动力学预测：在剥离本体后的表征上预测物体与环境的演化，并支持按动作条件化，供规划或 MPC 使用。
  4. 评测与可视化：把本体渲染、残差场景与预测未来分别可视化，方便判断因子化是否真的把本体分离干净。

这里最需要警惕的是「可微渲染」的代价：它要求已知本体几何与标定，且渲染本身要参与前向与反向，训练开销明显高于纯 2D 世界模型。若本体几何不准或相机外参漂移，渲染出的本体贡献会与真实观测错位，因子化反而引入系统性残差。

  • Robot-Factored World Models via Robot Rendering（CoRL 2026，本仓库官方论文）：本体因子化与可微机器人渲染的原始出处。
  • MoRE: Mixture-of-Experts for Multi-Physics Robotic World Models（arXiv 2611.25336，本轮 p397）：按物理机制分专家，与本仓库按建模对象分解构成正交维度。
  • PhyDEX: A Benchmark for Physical Reasoning in VLA Models via Dynamic Extrinsic Dexterity（arXiv 2611.26565，本轮 p400）：提醒世界模型必须真正预测重力、摩擦与惯量，而不只是把观测重建得像。
  • One Prior, Two Dynamics: Repurposing Video Diffusion Transformers for Self-Supervised Dynamics Modeling（arXiv 2611.26617）：视频扩散骨干复用于动力学建模的同期思路，可作为「不显式建本体几何」一侧的对照。
  1. 先核对本体几何与相机标定：这是全仓库最硬的前提。确认 URDF / mesh、相机内外参与论文设置一致，否则可微渲染一步就错。
  2. 按 README 建环境：可微渲染通常依赖特定版本的 PyTorch 与渲染 / 光栅化库，别用系统预装环境混跑。
  3. 先跑可视化不看指标：把本体渲染、剥离后的场景与预测未来并排看一眼，肉眼确认因子化确实生效，再开始扫指标。
  4. 做一次「去掉因子化」的消融：用同一套骨干跑不分本体的对照，确认收益来自因子化而非调参或数据量。
  5. 扫渲染精度与训练开销：渲染分辨率、可微步数直接影响显存与吞吐，报告指标时同时给出每步耗时。
  6. 换视角复跑：因子化若真的成立，换相机视角后本体贡献应能由几何一致地推出；只在单一视角成立多半是过拟合。

高频坑：把 robot rendering 当成普通图像分割（它要求可微且与本体状态绑定）；忽略相机外参漂移；用没有本体几何的数据集硬套方法；只报预测误差不报训练开销，让「更准」掩盖「更慢一个量级」。
