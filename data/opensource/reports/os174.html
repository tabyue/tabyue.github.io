从「训一个模型」到「养一个技能库」

主流具身智能的持续改进路径是：采集更多数据 → 继续微调 → 发新权重。这条路有三个老问题：灾难性遗忘、数据回流成本高、以及每次迭代都要重新做一遍全量回归验证。

ASPIRE 换了条路：模型权重不动，动的是技能库。Coding Agent 观察机器人执行任务的轨迹，定位失败发生在哪一步，改写对应的机器人程序，验证通过后把它作为一条可复用技能存进仓库。下一次遇到同类任务直接调用。

这个设计的直接好处是能力可审计：技能是代码，可以 diff、可以回滚、可以做上线前审查。在需要合规的工业与公共服务场景里，这比一个黑盒权重文件更容易被接受。

为什么现在是时机

这条路线成立的前提是 Coding Agent 本身足够强。2026 年前后，代码 Agent 在长上下文理解、多步修改、工具调用上的能力才真正达到可以自主修复机器人程序的水平。ASPIRE 的 v0.1 到 v1.0 的跃迁（新增魔方、LIBERO-Pro 99%）正对应底座模型的代际升级。

技能精炼循环

"""
ASPIRE 风格的核心循环：执行 → 诊断 → 修复 → 验证 → 固化。
"""
def aspire_round(skill_lib, task, agent, robot):
    program = skill_lib.retrieve(task)          # 检索已有技能
    trace = robot.execute(program)              # 在真机/仿真上执行
    if trace.success:
        return skill_lib.promote(program)       # 验证通过 → 固化

    diagnosis = agent.inspect(trace)            # Agent 检查执行轨迹
    patch = agent.repair(program, diagnosis)    # 定位失败步骤并改写程序
    trace2 = robot.execute(patch)
    if trace2.success:
        skill_lib.add(patch, version=next_ver)  # 新增版本，不覆盖旧版
    return skill_lib

注意最后一步是新增版本而不是覆盖——这与权重微调的本质区别就在这里：旧技能不会因为新技能的学习而退化。

分布式形态的重新定义

传统分布式训练 ASPIRE 的「分布式训练」
数据分片，多卡算梯度 多个 Agent 各练一项技能
需要参数同步（AllReduce） 只需合并技能库
通信开销随模型规模增长 通信量与模型规模无关

这个对比解释了为什么 ASPIRE 可以横向扩展：技能库的合并是集合并集操作，没有梯度同步的通信墙。

如何看这个 99%

这是实验室评测结果，不是通用自主能力的证明。基准任务的环境、物体集合和初始条件都是已知的，真机开放场景的成功率会显著低于这个数字。它说明的方向性是「技能库路线在封闭任务集上可以做到很高」，而不是「机器人已经通用」。

ASPIRE 版本化技能库 精炼 + 固化 无 高

与同类「代码自进化」工作（如 RoboRSI、EmbodiedEvo）相比，ASPIRE 的差异化在于把分布式扩展也重新定义了——不只是单个 Agent 写更好的代码，而是一组 Agent 并行练不同技能再合并仓库。

与 VLA 的关系是互补而非替代：VLA 擅长连续、柔顺、需要力控的动作生成；技能库擅长离散、可分解、需要长期积累的流程型任务。现实系统很可能是「VLA 做原子动作，技能库做流程编排」。
