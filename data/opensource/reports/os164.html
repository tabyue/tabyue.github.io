核心主张：世界模型应该被当成动作模拟器来验收，而不是视频生成器。

过去评估世界模型主要看 FVD、PSNR 这类视觉质量指标，但机器人用世界模型是为了两件事：

  1. 给定动作，画面是否真的按这个动作演化（动作忠实）
  2. 给定坏动作，画面是否会真地失败（能预测失败）

DreamTrue 把这两条立为验收标准，并给出可复用的实现路径。

为什么必须反事实：如果只在成功示范上训练，成功指示与动作几乎独立，模型会退化成「不管输入什么动作都生成完成画面」。这不是能力不足，而是数据分布决定的必然结果——所以必须人为造出失败样本。

为什么奖励模型不可省略：反事实样本没有配对真值未来（你没法拍到「如果这个坏动作执行了会怎样」），标准重建损失无处可算。奖励模型是这一空缺的替代品。

1. 动作条件渲染

把动作轨迹渲染成图像空间条件。渲染依赖相机与机器人的几何关系 $\hat{T} = T^{\star} + \delta$。

2. 离线几何校准

估计 $\hat{T}$，使渲染条件与目标视频在图像空间对齐，最小化重投影误差。

3. 跨本体监督训练

在多本体数据上训练同一套条件表示，实现跨本体迁移。

4. 反事实扩展

$$ a^{\text{cf}} = \mathcal{C}(a^{\text{rec}}, \epsilon), \quad \epsilon \sim \mathcal{U}(-\Delta, \Delta) $$

5. 缺陷标注与奖励模型

标注机器人缺陷、物体缺陷、交互缺陷三类，训练 $r_\psi(\hat{o}, a)$。

6. RL 后训练

$$ \max_{\theta} \mathbb{E}{a \sim p(a^{\text{cf}})} \big[ \mathbb{E}{\hat{o} \sim p_\theta} [\, r_\psi(\hat{o}, a) \,] \big] - \beta \, \mathrm{KL}(p_\theta | p_{\theta_0}) $$

标定误差自查

'''
量化渲染条件与目标视频中机械臂的错位
'''
import numpy as np

def calibration_error(render_mask, real_mask):
    inter = np.logical_and(render_mask, real_mask).sum()
    union = np.logical_or(render_mask, real_mask).sum()
    iou = inter / max(1, union)
    cy_r = np.argwhere(render_mask).mean(axis=0)
    cy_g = np.argwhere(real_mask).mean(axis=0)
    return float(1 - iou), float(np.linalg.norm(cy_r - cy_g))

排错要点

  • 画面很真但缺陷率高：奖励模型没训好或标注噪声大
  • 反事实样本被忽略：修改幅度太小，模型仍能靠先验补全成功结局
  • 跨本体掉点：动作条件渲染未对齐该本体运动学链，检查 URDF 与关节顺序
