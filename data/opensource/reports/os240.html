AI Worker（FFW，Freedom From Work）是 ROBOTIS 开源的作业型机器人整机项目。ROBOTIS 在机器人社区里长期以 Dynamixel 舵机、TurtleBot 与 ROS 2 生态著称，这个项目把积累从「零部件与移动底盘」延伸到「能干活的机器人本体」：以 C++ 为主的实现，配套官方站点 ai.robotis.com 提供文档与平台入口。

本站硬件类条目大多集中在机械臂、灵巧手、传感器这类部件级项目，整机级、带官方维护与 ROS 2 接口的开源平台相对稀缺。对想从零搭一套可复现真机平台、又不想被商用本体封闭接口绑死的团队，AI Worker 的价值在于它把本体、驱动与上层接口放在同一个可版本控制的仓库里。

需要如实说明：整机项目的开源不等于「下载即用」。加工、装配、电源、安全调试与 BOM 供应链都是真实成本，star 数与上手难度并不成正比。

从仓库组织与 ROBOTIS 既有生态可以推断出大致分层（具体以仓库文档为准）：

  1. 本体与执行层：Dynamixel 系列执行器与机械结构，负责关节驱动与力/位反馈。
  2. 固件与驱动层：C++ 实现的底层通信、电机控制与状态上报，贴合实时控制与嵌入式部署。
  3. ROS 2 接口层：把本体能力暴露成标准 topic / service / action，便于接入导航、操作与具身策略。
  4. 任务与平台层：面向实际作业场景的上层逻辑，配套官方站点的文档与工具。

这种分层与本站 ros2 模块反复强调的「1 kHz 运控与 50 Hz 策略放进同一台机器」是同一套工程哲学：下层保证实时与确定性，上层保留可替换性。对具身智能研究来说，可替换性尤其关键——同一套 VLA 策略换本体时，只要接口契约不变，就不必重写底层。

C++ 为主的语言选择也说明它偏向部署而非实验原型：研究侧可以照常用 Python 写策略，通过 ROS 2 桥接过来。

整机项目不适合用单一分数评估，建议按以下维度看：

  • 接口开放度：关节状态、力矩、控制指令是否都能通过标准接口读写。
  • 实时性：底层控制周期与上层策略频率是否解耦、能否稳定跑在目标频率。
  • 可复现性：BOM、装配公差、固件版本是否被完整记录。
  • 可维护性：官方是否持续更新、文档是否覆盖从装配到任务的全流程。
  • 社区与生态：能否复用 Dynamixel / TurtleBot / ROS 2 的既有工具链。

注意

  • 官方维护是优势也是约束：硬件迭代可能带来接口变更，长期实验要锁版本。
  • 整机调试的安全成本常被低估，务必把急停、限位、力矩上限当成第一优先级。
  • 与纯软件开源项目不同，这里的「可复现」包含物理装配误差，跨团队数字天然有差异。

对比部件级开源项目（如本站 os229 SO-ARM102、os234 OpenArm）：部件项目复现成本低、聚焦单一能力；AI Worker 是整机栈，覆盖更完整但装配与调试门槛更高。

对比商用本体（Franka、UR、各类人形）：商用本体精度与文档成熟，但接口与固件封闭、价格高；AI Worker 把本体纳入可版本控制的实验变量，代价是要自己承担集成与维护。

对比仿真优先平台（Isaac Lab、MuJoCo 生态）：仿真零硬件成本、可大规模并行；整机项目提供真实接触、摩擦、传动损耗与延迟，这些恰是 sim-to-real 里最难建模的部分。
