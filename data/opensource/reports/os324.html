支持在 RLDS、LeRobot v2/v3、Zarr、HDF5、Rosbag 之间互转，并提供 inspect（检查）、visualize（可视化）与 analyze（质量分析）能力，还能对接 HuggingFace Hub。topics 里 data-quality-checks、dataset-conversion、hdf5-to-rlds、lerobot、openvla、rlds 基本把工具边界说清楚了。

按仓库描述与 topics 可归纳为四块（结构性归纳，具体以 README 为准）：

  1. 格式适配层：为 RLDS / LeRobot v2 / LeRobot v3 / Zarr / HDF5 / Rosbag 各写一个 reader 与 writer，中间用统一的 episode / step 抽象解耦。这样新增一种格式只需加一对适配器，不必改转换逻辑——这就是站内数据章节里说的 O(N+M) 适配层。
  2. schema 对齐：不同格式对「一帧观测」的约定不同（图像编码、时间戳基准、动作维度顺序、本体状态字段）。转换层必须显式处理时间对齐与单位归一，否则转完的数据在训练时会出现隐性错位。
  3. 质量检查：data-quality-checks 类能力负责发现缺帧、NaN、时间戳倒序、动作越界、图像损坏等问题。
  4. Hub 对接：与 HuggingFace Hub 直连，便于把转换结果作为公开数据集分发。

为什么需要独立一层：多格式互转看着简单，真正的难点是语义等价——LeRobot v2 到 v3 的字段变化、RLDS 的 step 结构与 HDF5 的层级分组并不天然对应。把这层做扎实，训练代码才能只认一种 schema。

最小上手路径

git clone https://github.com/arpitg1304/forge.git
cd forge
pip install -e .
  1. 先读 README 确认当前支持的格式矩阵与 CLI 子命令名（reader/writer 的确切参数以仓库为准）。
  2. 用一个小规模公开数据集做往返转换：HDF5 → RLDS → HDF5，逐字段比对数值、时间戳与动作维度，确认语义无损。
  3. 跑 inspect / analyze，故意注入一帧缺失或 NaN，验证质量检查能否报出来。
  4. 做一次 LeRobot v2 → v3 转换，重点核对帧率与时间戳基准是否保持一致。
  5. 把转换结果推到 HuggingFace Hub 的私有仓库，验证分发链路。

常见坑

  • 把「格式转换」当成字节搬运：不核对时间对齐与单位，转完的数据训出来策略会莫名抖动。
  • 忽略 LeRobot v2/v3 的 schema 差异，直接按字段名硬映射。
  • 只转不验：转换后没有任何往返一致性检查，schema 漂移会一路带进训练。
  • 仓库约 185 star、创建未满一年，API 可能仍在变动，作为长期依赖前先锁定版本。
