RoboVerseOrg/RoboVerse 面向「可扩展、可泛化」的机器人学习，把仿真平台、数据集与基准三件事放进同一套接口（Apache-2.0，Python，约 1883 star）。同一份任务定义可以跨多个仿真后端运行，同一套数据格式可以跨本体复用，同一组评测指标可以在不同方法之间比较。

它要治的是机器人学习里最耗人力却最少被写进论文的成本：适配。换一个仿真器就要重写一遍任务与观测管线，换一个本体就要重做一遍数据转换，换一个基准就要重新对齐指标。RoboVerse 把这三件事收敛成「一个任务契约 + N 个后端适配层 + M 个本体适配层」，与站内 platform-engineering 模块讲的「统一评测契约、O(N+M) 适配层、基准可复现性」是同一套工程原则的一个具体实现。

为什么收录：作为 /learn/platform-engineering 与 /learn/embodied-data-engineering（数据格式标准与工具链）的一手工程样本。学它不是为了跑某个榜单分数，而是看「统一接口」落到代码里到底长什么样、哪些抽象真的省了适配成本、哪些只是把复杂度挪了个位置。

  1. 任务契约层：任务用与后端无关的描述定义（场景、物体、初始状态、成功判据、观测与动作空间），方法只面向这一层编程；
  2. 后端适配层：每个仿真器实现一个适配器，把任务契约翻译成该后端的场景加载、物理步进与渲染调用；新增后端只需加一个适配器，不动任务与方法；
  3. 本体适配层：机器人本体的 URDF / MJCF、关节映射、动作量纲与观测字段在适配层对齐，使同一份数据能被不同本体消费；
  4. 数据层：统一的 episode 格式，把观测、动作、任务、时间戳与元信息写在一起，强调跨本体复用而非单一任务专用；
  5. 评测层：一组固定指标与可复现的评测流水线，让不同方法在同一任务契约下可比；
  6. 上层：配套大规模机器人学习数据集与基准，目标是可迁移性评估，而不是单一榜单的最优分数。

读法：重点看「成功判据」放在哪一层。判据若下沉到后端适配器，跨后端可比性就丢了；判据若完全脱离物理状态，又容易被方法侧的取巧行为绕过。这个边界设计是统一平台最难也最值钱的部分。

def evaluate(backend, policy, task, episodes=100, horizon=200):
    '''Same contract, one adapter per backend.'''
    env = backend.make(task)
    ok = 0
    for _ in range(episodes):
        obs = env.reset()
        for _ in range(horizon):
            obs, _, done, _ = env.step(policy(obs))
            if done:
                break
        ok += int(env.is_success())
    return ok / episodes

公开可得的是工程事实：Apache-2.0、Python、约 1883 star、2026-11-09 仍在推送，仓库以「统一平台 + 数据集 + 基准」为定位。仓库不提供一份可以跨所有方法直接引用的统一分数表，本站也不替它编造成功率。

对统一平台，该核对的是四项，比单一榜单分数更能决定它值不值得进研究管线：

  1. 跨后端一致性：同一任务、同一种子在两个后端上的轨迹与成功率差异是否落在可解释范围内；
  2. 适配层真实成本：新增一个后端 / 本体实际要写多少代码、要碰多少处任务定义；
  3. 成功判据的抗取巧性：判据是否基于物理状态而非渲染像素或方法侧自报；
  4. 数据格式的跨本体保真：动作量纲、时间对齐、本体状态字段在转换后是否仍然自洽。
