核心主张：指令定位不只发生在空间里，也发生在时间里。

现有 VLA 基准绝大多数假设「看到当前帧就知道指令指的是哪个物体」。这个假设在实验室里成立，在真实场景里经常崩：台面上并排放着六支外观相同的试管，「把刚才污染的那支拿走」这句话，只有看过前面几分钟的人才能执行。

GiT 把这个能力单独抽出来做成基准，价值在于——它让时序定位成为可测量的独立指标，而不是被任务成功率掩盖的隐藏因素。

为什么需要三个子集：real 提供真实动力学与噪声，sim 提供规模与可控变量，umi 提供低成本的采集扩展路径。三者互补，可以在不同预算下做消融。

对 VLA 训练的直接价值：同步多视角 RGB + 本体感知 + 时序真值的组合，既可用于训练记忆型策略（如带 Gated DeltaNet / 状态演化记忆的架构），也可用于评估策略是否真的在用历史信息。

任务构造原则

每个场景含若干感知近同的物体，指令所指对象由 episode 的时序结构唯一确定：

$$ o^{\star} = \arg\max_{o \in \mathcal{O}} \; p(o \mid \text{instr}, \tau_{0:t}) $$

而 $p(o \mid \text{instr}, f_t)$（仅当前帧）近似均匀——这是设计的硬性要求。

HDF5 schema

每条 episode 为单个自包含文件 {task}_episode{N}.hdf5；图像流以编码字节存储（变长 uint8），需 cv2.imdecode / PIL.Image.open 按需解码；双臂键名为 puppetLeft / puppetRight。

时序真值

$$ \text{demo}: [0, d], \quad \text{subtask}_k: [s_k, e_k] $$

评测可只取歧义段 $[d+1, T]$。

'''
读取一条 GiT episode：按需解码图像 + 读取时序标注
'''
import h5py, cv2, numpy as np

def load_episode(path, cam='cam_high', every=10):
    with h5py.File(path, 'r') as f:
        frames = f[cam][:]                       # (T,) 变长 uint8 编码字节
        imgs = [cv2.imdecode(np.frombuffer(b, np.uint8), cv2.IMREAD_COLOR)
                for b in frames[::every]]
        qpos = f['puppetLeft']['qpos'][:]        # (T, D) 本体感知
        segs = f.attrs.get('subtask_ranges')     # 时序真值
    return imgs, qpos, segs

建议的验证顺序

  1. 先测基线：用只吃当前帧的模型跑歧义段，确认它确实失败（这是基准有效性的前提）
  2. 加记忆：接入历史压缩模块，观察定位准确率提升幅度
  3. 消融序列长度：找出消歧所需的最短历史窗口
  4. 跨子集迁移：sim 训练 → real 评测，量化域差距

排错要点

  • 解码极慢：不要一次性解码全部帧，按批解码并缓存
  • 定位准确率不涨：检查是否把演示段也喂给模型（演示段已包含消歧信息，会虚高）
  • 真机子集掉点：先查多视角时间同步，再看相机外参
