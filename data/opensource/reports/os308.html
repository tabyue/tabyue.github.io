embodied-ai-nexus/Eden 是一个 Agent 原生（agent native）的机器人学习框架，约 305 star（2026-11-21 核验），Apache-2.0 许可，Python，2026-05-10 创建、11-20 仍在活跃更新，配有项目主页。topics 覆盖 real2sim2real、robot-learning、robotics、sim2sim，说明它的重心不在单个算法，而在把「真实数据 → 仿真 → 策略训练 → 再回真实」的闭环组织成可复用的工程结构。

「Agent 原生」在这里的含义值得展开：传统机器人学习框架多以数据集、环境或模型为中心组织代码，而 Agent 作为一个有记忆、会调用工具、能按目标分解任务的一等公民，往往只能靠上层脚本临时拼。Eden 把 Agent 抽象放进框架核心，让策略、仿真环境与数据管线都围绕 Agent 的观测—决策—执行循环来定义，这对当前 VLA + LLM 规划 + 工具调用混合的具身系统更自然。

它值得单独收录，是因为本轮五篇论文里有三篇（PGX、CauSyncVLA、PhyDEX）都在处理「模型之外」的时序组织、状态同步与阶段评测，而 Eden 正是把这类外层结构沉淀成框架的尝试；配合站内 /learn/embodied-agent 的分层 Agent 架构与 /learn/physics-simulation 的仿真选型一起读最合适。

按 topics、仓库定位与项目主页，可以把 Eden 的组织方式归纳为五层（注意：结构性归纳，具体模块与 API 以仓库 README 为准）：

  1. Agent 抽象层：定义 Agent 的观测、记忆、目标与工具调用接口，把「会调工具的策略」与「只输出动作的策略」统一到同一套循环里。
  2. 多物理仿真层：整合多种物理后端，支持同一任务在不同动力学假设下训练与对照，对应 multi-physics 与 sim2sim 两个 topic。
  3. Real2Sim2Real 数据层：把真实采集的场景 / 轨迹重建进仿真，训练后再把策略迁回真机，形成闭环；这一层决定数据格式与时间对齐契约。
  4. 训练与评测层：统一管理策略训练、阶段化评测与指标记录，避免训练标注与部署判定口径不一致。
  5. 工具与集成层：对接上层 LLM / VLA 与外部工具，让 Agent 能把能力暴露成可调用接口。

与「一个仿真器 + 一份训练脚本」的轻量组合相比，Eden 的价值在于把闭环里的契约（时间对齐、坐标系、数据格式、评测口径）显式化。这些契约恰恰是 /learn/embodied-data-engineering 的数据格式标准与 /learn/platform-engineering 的策略评测基础设施反复强调的东西；代价是框架本身有学习成本，小项目可能用不满。

  • PGX: Physically Grounded Execution for Long-Horizon Humanoid Loco-Manipulation（arXiv 2611.26596，本轮 p401）：把时序与空间一致性交给免训练外层结构的实例，与 Eden 的框架化思路同源。
  • CauSyncVLA: Causal Latent World Modeling for Asynchronous Robot Control（arXiv 2611.25667，本轮 p398）：感知记忆与动作块的时间对齐问题，正是闭环框架必须在数据契约层解决的那类问题。
  • MoRE: Mixture-of-Experts for Multi-Physics Robotic World Models（arXiv 2611.25336，本轮 p397）：按物理机制分工的世界模型，可视为 Eden 多物理后端里一种可选的世界模型实现。
  • Eden 项目主页与仓库 README（embodied-ai-nexus.github.io/Eden/）：框架定位、支持的仿真后端与示例任务的原始出处，先读它再决定是否引入。
  1. 先读项目主页再装依赖：多物理框架通常对仿真后端、CUDA 与系统库版本敏感，按主页给出的环境矩阵建虚拟环境最省事。
  2. 跑通一个最小的 real2sim2real 闭环：先选一个自带示例任务，确认「真实数据导入 → 仿真重建 → 训练 → 回真机评测」四段都能走通，再替换自己的数据。
  3. 核对时间对齐与坐标系契约：把每条数据的时间戳、基座坐标系与动作空间打印出来比对，这是闭环框架里最容易静默出错的地方，错误不会报错只会让成功率缓慢下降。
  4. 逐个切换物理后端：sim2sim 的价值在于对照，固定策略只变后端，观察哪些结论是动力学假设带来的。
  5. 分层验证 Agent 抽象：分别关闭工具调用、清空记忆、只保留底层策略，确认收益确实来自 Agent 结构而非某个隐藏的超参。
  6. 记录每段的吞吐与延迟：闭环框架里数据重建与仿真往往比训练更耗时，先量清楚再优化。

高频坑：把 Eden 当成又一个仿真器去比渲染精度（它的定位是编排层）；用单一物理后端跑完却声称验证了多物理；忽略 real2sim2real 的重建误差，把仿真里的成功直接当成真机预期。
