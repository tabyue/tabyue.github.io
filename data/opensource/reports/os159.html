核心主张：世界模型的预演空间应该是三维，而不是像素。

现有 WAM 大多建立在预训练视频生成器之上，用图像或视觉 latent 表示世界演化。但机器人交互发生在 公制三维空间，而图像是 视角相关的投影——同一段物理位移在近处占几百像素、远处占几十像素，相机一动像素坐标全变。让模型在像素空间预测未来，等于强迫它同时学物理与投影几何。

UNITAS 的做法

在一次交互内建立共享的公制三维坐标系，三类量全部落在其中：

  • 观察：视觉 token 经世界对齐 3D 位置编码落地到三维位置
  • 动作：动作流——人手关键点与机器人夹爪的 3D 点轨迹
  • 环境响应：场景流——以动作流为条件的场景点位移

预测目标从「未来图像」换成「三维位移场」，投影不再是需要在隐空间里反推的量。

为什么参数效率高

1.7B 打过 6B 与 8B，差距不在容量而在表示空间：当三维物理量直接可加减时，模型不需要花容量去隐式还原深度与视角。这对边缘部署是直接红利。

1. 动作流（action flow）

$$ \mathcal{A} = {\, p_i(t) \in \mathbb{R}^3 \mid i = 1 \dots N_a,\; t \in [t_0, t_0+H] \,} $$

把末端（夹爪或人手关键点）在时间窗内的运动表示为三维点轨迹。人手与机器人末端共用这一表示，只是点的语义绑定不同——这直接打通了人类视频数据的复用路径，无需额外重定向模块。

2. 场景流（scene flow）

给定动作流，场景点 $q_j$ 的位移

$$ \Delta q_j = f_\theta\big(q_j(t_0), \mathcal{A}, \mathcal{O}\big) $$

$f_\theta$ 即模型要学的 物理演化算子。

3. 世界对齐 3D 位置编码

对第 $k$ 个视觉 token，其在世界系的三维位置由深度（或推断深度）反投影得到：

$$ c_k = R^\top (d_k K^{-1} u_k - t) $$

位置编码 $PE(c_k)$ 直接加在 token 上，使注意力在 三维邻近性 上聚集，而非在图像网格邻近性上聚集。

4. 物理时间轨迹分词器

一条点轨迹经可学习映射压缩为单 token：

$$ z_i = \phi(\tau_i; c_i) \in \mathbb{R}^{d}, \quad c_i = p_i(t_0) $$

序列长度从 $O(T \cdot N)$ 降到 $O(N)$；且时间以 物理量 而非帧序号进入模型，便于处理不同采样率的数据源。

5. 双用途接口

同一个接口既支持 直接动作执行（从观察与指令解码动作流），也支持 动作条件场景预测（给定候选动作流预测场景点位移，用于规划与评估）。

位移误差自查

"""
检查预测位移场与真值的误差（复现 49% 降幅的关键指标）
"""
import numpy as np

def flow_error(pred_xyz, gt_xyz, valid=None):
    # pred_xyz / gt_xyz: (T, N, 3) 场景点位移场
    # valid: (T, N) 布尔掩码，剔除遮挡点
    if valid is None:
        valid = np.ones(pred_xyz.shape[:2], dtype=bool)
    d = np.linalg.norm(pred_xyz - gt_xyz, axis=-1)
    return float(d[valid].mean()), float(np.percentile(d[valid], 90))

排错要点

  • LIBERO 能复现但真机掉点严重：优先查 手眼标定与点云尺度，而不是调模型
  • 无深度输入时掉点明显：检查世界对齐位置编码分支是否退化成随机初始化
