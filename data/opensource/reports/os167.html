核心主张：导航泛化能力来自大模型的通识，而微调恰恰会破坏它。

这是一个反直觉但逻辑自洽的判断。领域微调的本质是把模型往某个数据分布上拉——在导航任务上就是往 HM3D / MP3D 那几套仿真场景拉。模型在这些场景里变强了，代价是通识推理能力被覆盖。于是遇到没见过的房间布局、没见过的物体实例，微调模型就崩了（论文数据：下降 45%+）。

SuperNav 的解法不是「微调得更好」，而是「压根不微调」。 让冻结的 MLLM 做它擅长的事——理解「茶几上那副眼镜」这个模糊指代、推理出「先去客厅、再找茶几、再辨识眼镜、最后停在可操作距离」这样的动作序列；让确定性的导航工具做它擅长的事——避障、路径规划、轨迹执行。

接口是本项目的关键设计。 两层之间怎么通信？如果让 MLLM 输出文本指令再由另一个模型解析，就又引入了歧义。SuperNav 让 MLLM 直接在图像上点——输出归一化 2D 坐标。这个设计的巧妙之处在于：图像坐标是 MLLM 视觉能力最强的模态，同时又是下层几何模块最容易消费的输入。而且因为 MLLM 每步都能看到新画面，它能基于视觉反馈持续修正，形成闭环。

为什么值得工程关注：整套方案绕开了「为每个场景收集导航数据并微调」这个昂贵环节。对没有大规模导航数据积累的团队，这提供了一条低成本起步路径。

统一视觉点位接口

MLLM 在观测图像 $I_t$ 上标注路点：

$$ p_t = (u_t, v_t), \quad u_t, v_t \in [0, 1] $$

下层通过相机内参与深度把点位投影进 3D 地图：

$$ P_t^{\text{3D}} = \pi^{-1}(p_t, d(p_t); K, T_{\text{map}\leftarrow\text{cam}}) $$

闭环修正

$$ p_{t+1} = \text{MLLM}(I_{t+1}, \ell, \text{history}) $$

每一步都重新看画面并更新路点，因此遮挡、走错、目标变化都能被自然处理。

Agent Harness 四类技能：主动探索 / 多视角候选复查 / 卡死恢复 / 长程拓扑进度跟踪。

点位投影检查

'''
把 MLLM 标注的归一化点位投影到 3D 地图坐标
'''
import numpy as np

def unproject(p, depth, K, T_map_cam):
    u, v = p
    h, w = depth.shape
    d = depth[int(v * (h - 1)), int(u * (w - 1))]
    if not np.isfinite(d) or d <= 0:
        return None                      # 点位落在无效深度上，需重新标注
    x = (u * w - K[0, 2]) * d / K[0, 0]
    y = (v * h - K[1, 2]) * d / K[1, 1]
    P_cam = np.array([x, y, d, 1.0])
    return (T_map_cam @ P_cam)[:3]

排错要点

  • 点位投影到无效深度：让 MLLM 重新标注，或先做主动探索补一帧观测
  • 长程任务中途丢失进度：Harness 的拓扑进度跟踪没接上，检查历史摘要是否传入 MLLM
  • 实机抖动：路点更新频率与控制周期不匹配，需要把点位变化做平滑后再下发
  • 卡死恢复不触发：检测阈值设得太宽，先收紧再看误触发率
