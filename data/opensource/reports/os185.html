robonix 的定位是 The Agentic Operating System for Robots。

ROS 2 解决了什么、没解决什么

ROS 2 提供的是通信与组件化基础设施：节点、话题、服务、动作、参数、生命周期管理、DDS QoS。它把「把机器人软件拆成可复用的进程」这件事做得很好。

但它刻意不回答下面这些问题：

  • 大模型（VLM / VLA）应该挂在栈的哪一层？
  • 技能库怎么组织，才能让 Agent 发现并决定调用哪个技能？
  • 一个长程任务失败后，谁来诊断、谁来重试、谁来降级？

这些是运行时语义问题，不是通信问题。robonix 想补的就是这一层。

为什么叫「操作系统」

类比操作系统的职责——管理资源、抽象硬件、为应用提供统一接口——robonix 想做的是：

  • 把模型能力（VLM 理解、VLA 动作生成）当作可调度资源；
  • 把技能当作应用，通过统一接口注册与调用；
  • 把机器人硬件抽象掉，让上层不直接面对驱动。

Skill-MD 这个设计

topics 里的 skill-md 暗示技能以 Markdown 描述的方式组织。这个设计的意义在于：

  • 大模型天然擅长读 Markdown，可以直接理解「这个技能做什么、需要什么输入、有什么前置条件」；
  • 技能描述与文档合一，不会像硬编码注册表那样文档与实现脱节；
  • 人可以直接编辑，不需要改代码就能加一个新技能。

这与当前 Agent 生态里「用自然语言/Markdown 定义工具」的方向一致。

为什么用 Rust

机器人运行时是长期运行、不能崩的系统。Rust 的所有权和类型系统在编译期消除数据竞争与一大类内存错误，这对一个要连续跑几百小时的控制/编排进程来说，价值高于开发速度。

分层

   任务 / 用户指令
        │
        ▼
   Agent 编排层（理解意图、分解任务、诊断失败）
        │  调用决策
        ▼
   技能库（Skill-MD 描述，可发现）
        │
        ▼
   模型能力层（VLM 理解 / VLA 动作生成）
        │
        ▼
   硬件抽象（机器人本体、传感器）

与 ROS 2 的关系

二者不是替代关系。robonix 关注的是运行时语义（模型怎么接、技能怎么被发现和调用），ROS 2 关注的是进程间通信。实践中可以：ROS 2 负责底层驱动与节点通信，robonix 这类运行时负责上层的 Agent 编排与技能管理。

Skill-MD 的调用链

Agent 读技能清单（Markdown）
    → 依据当前任务与观测选择技能
    → 按描述组装输入参数
    → 调用技能（内部可能是 VLA 推理、也可能是传统规划器）
    → 检查结果，失败则重新选择或上报

关键在「可发现」：Agent 不是被硬编码告知有哪些技能，而是从描述里读出来。新增技能不需要改 Agent 代码。

  • RAI: ROS 2 原生的具身 AI Agent 框架 — 同类思路的 Python 实现，可与 robonix 对照评估。
  • Embodied Turing Machines: Stateful Code for Robotic Manipulation — 以有状态代码作为机器人操作表示，与「技能可发现、可复用」的方向相关。
  • Recova: Agent-Guided Failure Recovery — Agent 主导的诊断—恢复闭环，是 Agentic 运行时的典型应用场景。

建议的上手顺序

  1. 先跑最小示例：确认运行时能启动、能加载技能清单；
  2. 用 Markdown 写一个自己的技能，验证 Agent 能发现并调用它——这一步是验证 Skill-MD 机制是否真的可用；
  3. 接入一个模型：先接 VLM 做理解，再接 VLA 做动作；
  4. 接真实硬件或仿真：确认硬件抽象层能对接你的本体。

评估要点

上手时重点验证三件事：

  • 技能发现是否真的动态：加一个新技能是否需要改 Agent 代码；
  • 失败处理路径：技能执行失败后，Agent 是否会重试 / 换技能 / 上报，而不是直接崩溃；
  • 长期运行稳定性：连续跑数小时是否出现内存增长或死锁——这也正是选 Rust 想解决的问题。

定位性收益

  • 补齐 ROS 2 之上的运行时语义层：模型接入、技能发现、Agent 编排；
  • Rust 的内存与并发安全：适合长期运行的机器人进程；
  • Skill-MD 降低技能扩展成本：加技能不改代码；
  • 402 stars、维护超一年：有一定社区基础。

需要注意的边界

  • 较新的运行时：生态成熟度、硬件适配广度与 ROS 2 不可比；
  • Rust 门槛：团队若无 Rust 经验，二次开发成本需要考虑；
  • 与既有栈的整合：如果已深度绑定 ROS 2，需要评估接入方式（是替换还是叠加）；
  • MulanPSL-2.0：木兰宽松许可证，商用前建议按团队合规流程确认。

选型建议

如果你的痛点是「VLA/VLM 接进来之后，技能与编排没人管」，robonix 的设计思路值得参考——尤其是 Skill-MD 让大模型直接读懂技能清单这一点，实现成本不高但可以自己先做。如果已有成熟的 ROS 2 栈且运行良好，不必替换，可以先只借鉴技能描述层。

怎么选：

  • 只需要通信与组件化 → ROS 2；
  • 已有 ROS 2 且要加 Agent 能力 → RAI 这类 ROS 2 原生框架，接入成本最低；
  • 从零建一个以 Agent 为中心的运行时、且重视内存安全 → robonix。

三者是叠加而非替代关系，实际系统常常是「ROS 2 打底 + Agent 框架在上」。
