是什么

VPP2 是世界动作模型（World Action Model, WAM）路线的开源实现。WAM 是当前机器人学习的主流范式之一：把视频生成模型「预测未来画面」的能力，迁移为机器人「该怎么动」的动作能力。直觉上一个能在脑中推演未来的机器人，理应知道下一步该做什么。

为什么这条路线成立：视频生成模型在海量视频上学会了世界的物理演化规律——东西会怎么落、会怎么滑、手碰到之后会怎样。这些规律恰好是机器人决策最需要的先验，而它不需要任何机器人标注就能从视频里学到。

关键分岔在于动作头接在哪里：

  1. 接在预测出的未来表示上（VPP2 这类 WAM）——先想清楚世界会变成什么样，再决定怎么动
  2. 直接接在当前观测编码上（常规 VLA）——看到什么就动什么

路线 1 的优势是未来预测提供了稠密监督：动作标签每个时刻只有一个向量，而未来画面的每个 patch 都是监督信号。这解释了为什么 WAM 在数据效率上通常更好。

VPP2 要解决的问题

论文与技术报告强调的核心问题是：如何让 WAM 在开放环境下泛化。

这个问题之所以难，是因为视频预测模型在训练分布上学到的演化规律，一旦场景换到没见过的物体、光照、背景，预测质量会迅速下降，而动作头完全依赖这个预测。所以 WAM 的泛化能力上限，实际上被未来预测的分布外鲁棒性锁死了。

VPP2 的做法是把提升押在预训练上，而不是靠推理时增强——这也是它能声称「不使用 Agent RSI」的原因。

推理最小示例

以下为结构示意，具体 API 请以仓库 README 为准：

from vpp2 import VPP2Policy

policy = VPP2Policy.from_pretrained('roboterax/vpp2')

obs = env.reset()
while not done:
    # 关键：一次调用输出一个动作块，而不是单步动作
    chunk = policy.predict_action_chunk(
        obs,
        instruction='把红色方块放到蓝色碗里',
        horizon=16,
    )
    # 连续执行整个块再重新观测，避免 stop-and-go
    for a in chunk:
        obs, done = env.step(a)

关键实践提醒

执行动作块时不要每步都重新推理。WAM 的推理成本远高于单步执行，逐步调用会把任务时长全部耗在等待上。如果必须缩短停顿，可参考 RACE（p196）的思路：把切换时刻建模出来，就能安全地用更长动作块。

常见坑

  • 视频预测的分辨率不匹配：动作头依赖的隐变量分辨率与训练时不一致会导致动作幅度错误，检查配置里的分辨率参数
  • 指令模板不一致：RoboDojo 的指令格式有固定模板，自定义改写会掉点
  • 显存不足优先降 batch 而不是降分辨率：降分辨率会改变预测分布，直接破坏模型行为

相对增量才是重点

VPP2 的价值不在于 32.26% 这个数，而在于：

  1. 它不使用额外数据，说明预训练配方可迁移
  2. 它不使用 Agent RSI，说明推理时不靠外挂

第 3 点尤其重要：榜单总分第一有时是靠在擅长维度上刷分。三个单项同时第一，说明模型能力是均衡的。
