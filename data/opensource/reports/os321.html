PlantPotatoOnMoon/TwoPass 是《TwoPass: Draft-Guided Few-Step Video Prediction for Robotic Manipulation》的官方代码，Apache-2.0、Python，2026-11-18 创建、11-20 更新，约 29 star，是本轮最新鲜的仓库。

它面向动作条件视频预测（action-conditioned video prediction）：机器人执行一段动作后，未来画面会怎样？标准扩散/流匹配模型要几十步去噪才能出图，放在策略在环的推演里太慢。TwoPass 的思路是「先出草稿、再少步精修」——第一遍生成一个粗糙但结构正确的草稿，第二遍以草稿为条件只用很少的步数完成细化，配合 flow matching 与 self-conditioning 把采样链压短。

topics 覆盖 diffusion-models、few-step-generation、flow-matching、video-diffusion、robot-manipulation、bridge-dataset、language-table、pytorch。

按论文标题与仓库 topics 可归纳为两遍式结构（结构性归纳，具体以代码为准）：

  1. Draft Pass（草稿）：以当前观测与动作序列为条件，快速生成一个低精度的未来帧/潜表示。草稿不追求纹理正确，只要求物体位置、机械臂形态与运动方向大致对。
  2. Refine Pass（精修）：把草稿作为额外条件送入同一个（或轻量）网络，用少步 flow matching 求解从噪声到目标的流，self-conditioning 把上一轮输出回灌为条件，避免重复长链采样。
  3. 动作条件注入：动作序列通过交叉注意力或自适应归一化逐帧注入，保证「改一个动作、未来画面跟着改」，而不是生成一段与动作无关的视频。
  4. 训练目标：以 flow matching 的向量场回归为主，可能配合草稿一致性损失；评测在 Bridge Dataset 与 Language-Table 等机器人操作视频上做。

为什么值得看：它不否认「生成未来画面」这条路，而是把这条路最被诟病的推理成本往下压，因此与 PhysVAM（p415）的「干脆不生成」形成干净的对照实验条件。

最小上手路径

git clone https://github.com/PlantPotatoOnMoon/TwoPass.git
cd TwoPass
pip install -r requirements.txt
  1. 先读 README 确认权重/数据（Bridge Dataset、Language-Table）的下载方式与推理脚本入口。
  2. 用单条轨迹跑一次推理，记录去噪步数 $N$、单步耗时与端到端延迟，确认「few-step」的实际量级。
  3. 做步数扫描：$N = 1,2,4,8,16$，画 FVD/LPIPS（或仓库给定指标）—步数曲线，找质量拐点。
  4. 做动作敏感性检查：把同一初始帧配两条不同动作，比较生成未来是否随之改变，验证动作条件真的生效。
  5. 做草稿消融：去掉 Draft Pass、直接用同等步数从纯噪声生成，量化草稿带来的收益。

常见坑

  • 仓库很新（11-18 创建），权重与数据可能尚未放齐，先确认可复现性再排期。
  • 只比 FVD 不比延迟，会丢掉「few-step」这件事的全部意义。
  • 用固定动作或单帧条件评测，容易把画面连续性当成动作条件能力。
