核心主张是让策略自己的执行反馈反过来修正训练监督：从视频里提取人体运动作为人形跟踪的参考，但视频重定向得到的参考轨迹未必是控制器实际能跟得住的；MimicX 用 rollout 诊断定位困难时间窗，再据此精修监督信号，形成「策略在环」（policy-in-the-loop）的闭环，而不是一次性把视频动作喂给策略。仓库带 CPU 测试工作流，并在 Hugging Face 上公开策略权重（Shuaijun/MimicX-Policies）与资产（Shuaijun/MimicX-Assets），README 展示了 G1 网球挥拍等高动态动作的跟踪效果。

按 README 与论文描述可归纳为四块（结构性归纳，具体以仓库文档为准）：

  1. 视频到运动的重定向：从单目／多视角视频提取人体运动，转换成 G1 等本体可表达的参考动作序列；这一步的误差是后续跟踪的主要噪声源。
  2. 跟踪策略训练：以重定向结果为监督训练全身运动跟踪策略，输出关节级控制指令；高动态动作（挥拍、快速转体）对接触与平衡最敏感。
  3. Policy-in-the-Loop 诊断：把训练中的策略拿去 rollout，按时间窗统计跟踪误差，识别「哪些片段反复学不好」——是重定向本身有噪声、动作超出本体可达范围，还是控制器跟不上。
  4. 监督精修：依据诊断结果调整这些困难片段的监督（重加权、修正或剔除），再训练下一轮策略，形成闭环。

cd MimicX
# Python 3.10+，按 pyproject.toml 安装依赖
  1. 先跑仓库自带的 CPU tests 工作流，确认环境可用；这是 README 里明确给出的健康检查入口。
  2. 从 Hugging Face 拉取 Shuaijun/MimicX-Policies 的公开策略权重与 Shuaijun/MimicX-Assets 资产，先在仿真里复现 README 展示的跟踪动作（如 G1 网球）。
  3. 记录基线跟踪误差，尤其按时间窗拆开看，不要只报全局均值——policy-in-the-loop 的全部价值都在困难片段的定位上。
  4. 复现诊断环节：跑一次 rollout，导出误差随时间窗的分布，人工核对高误差窗对应的视频帧是否真有重定向噪声。
  5. 做「有监督精修 vs 无精修」对照，同样训练预算、同样的重定向输入，比较困难窗的误差下降幅度。
  6. 换一条高动态动作序列做跨动作泛化测试，验证精修没有过拟合到单条视频。
