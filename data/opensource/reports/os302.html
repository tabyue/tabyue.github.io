为什么值得看：站内 /learn/ros2 讲运行时分层、/learn/mobile-robot-navigation 讲 SLAM 与 Costmap、/learn/ai-infra 讲边缘部署，这三块在文档里通常是分离的；这个仓库把它们放在同一套可运行的 launch 配置里，正好可以当作一条端到端的实机链路来读。

  1. 驱动与 bringup 层：底盘电机、IMU、LiDAR 的 ROS 2 驱动与统一启动配置，是所有上层能力的入口。
  2. 状态估计与 SLAM 层：里程计融合与建图，产出供导航使用的地图与位姿。
  3. 导航层（Nav2）：全局 / 局部规划、Costmap 分层、行为树与恢复行为；导航与回充都是典型的长时 ROS 2 action。
  4. 自动回充（docking）：把「低电量 → 自主回桩 → 对准 → 充电确认」做成可调用 action，是移动机器人连续作业的关键闭环。
  5. 仿真与数字孪生：Gazebo + URDF，让导航策略先在仿真里回归再上真机。
  6. 边缘部署：topics 里的 nvidia-jetson 指向本体侧算力布局，与远端策略服务形成对照。

  1. 先按文档站锁版本：ROS 2 Jazzy 与 Nav2、Gazebo 的版本组合很敏感，先照 docs.openamrobot.ai 建环境，别用系统里已有的其它 ROS 发行版混跑。
  2. 只跑 bringup：先把驱动与 /tf、/odom、/scan 打通，用 rviz 确认坐标系与时间戳正确；这一步没过，后面 SLAM 与导航的报错都很难定位。
  3. Gazebo 里先建图再导航：用仿真跑一遍 SLAM 与 Nav2，保存地图；真机建图前先确认雷达与 IMU 标定参数。
  4. 把 action 列出来：用 ROS 2 命令行列出所有 action server（导航、回充等），记录每个的 goal / feedback / result 结构——这既是调试清单，也是接 ROSMonitoring 时的插桩清单。
  5. 回充单独验收：自动回充涉及接触与位姿对准，必须记录成功率、对准误差与失败原因标签，和站内 /learn/ai-infra 深化的任务层指标一致。
  6. 再考虑双臂上身：底盘稳定后再接 openamr-upperbody-sw，避免两个子系统同时调试。
