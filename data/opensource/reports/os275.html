NVIDIA/warp 是一个用 Python 写 GPU kernel 的开源框架（Apache-2.0）：用 Python 语法的一个子集写计算内核，运行时 JIT 编译成 CUDA / C++ 原生代码，面向仿真、机器人与机器学习里「现成算子不够用、得自己写算子」的部分。它提供数组、稀疏矩阵、网格、哈希网格等数据结构，内置自动微分（wp.Tape），并支持 CUDA Graphs 重放与 PyTorch / JAX / NumPy / DLPack 互操作。

为什么收录：本站此前已收 os273（Alloy，基于 Newton / MuJoCo Warp 的多材料并行物理引擎），而 Newton、MuJoCo Warp 以及大量可微接触动力学、梯度型策略学习工作的底层都落在同一套 kernel 抽象上。学 Warp 不是为了换框架，是为了读懂一件事——为什么这一代仿真器能把梯度一路传到接触点。robot-dynamics#0 讲拉格朗日方程与 RNEA，p360 讲从本体感知反推接触力，而 Warp 提供的是「把力对参数的导数算出来」的工程底座。

另一个值得对照的点：Warp 用 CUDA Graphs 压低高频小 kernel 的启动开销，与 p361（FAME-QP 用 CUDA Graphs 重放 MPC 迭代）是同一类系统级优化思路——优化对象都是每周期固定开销而非大矩阵吞吐。

  1. 编程层：用 @wp.kernel 装饰的 Python 函数，函数体内是受限的 Python 子集（显式类型、无动态分配），由 Warp 在首次调用时 JIT 到 PTX / C++；
  2. 数据层：wp.array 为主，另有稀疏矩阵、体素网格、哈希网格、BVH 等物理求解常用结构，全部可在 host 与 device 之间显式搬移；
  3. 微分层：wp.Tape 记录 kernel 执行，反向模式自动微分把梯度从输出传回输入——这是可微仿真的核心，也是「接触力对初始状态 / 控制参数求导」能落地的前提；
  4. 执行层：CUDA Graphs 把一串高频小 kernel 录制成图反复重放，消掉反复 launch；模块缓存让 JIT 结果跨进程复用；
  5. 互操作层：通过 DLPack 与 PyTorch / JAX 近乎零拷贝交换张量，可把 Warp kernel 嵌进现有训练管线，而不必把整条管线搬进 Warp。

读法：先看 wp.Tape 怎么处理「kernel 里有分支 / 原子操作」时的梯度记录——这决定了接触、碰撞这类不连续算子能不能被反传，也是可微仿真最容易出偏差的地方。

import warp as wp
import numpy as np

wp.init()

@wp.kernel
def add_kernel(a: wp.array(dtype=wp.float32),
               b: wp.array(dtype=wp.float32),
               out: wp.array(dtype=wp.float32)):
    i = wp.tid()
    out[i] = a[i] + b[i]

n = 1_000_000
a = wp.array(np.ones(n, dtype=np.float32), dtype=wp.float32)
b = wp.array(np.full(n, 2.0, dtype=np.float32), dtype=wp.float32)
out = wp.zeros(n, dtype=wp.float32)
wp.launch(add_kernel, dim=n, inputs=[a, b, out])
print(float(np.max(np.abs(out.numpy() - 3.0))))  # expect 0.0

# 自动微分：把标量输出对输入求导
@wp.kernel
def scale_sum(a: wp.array(dtype=wp.float32),
              s: wp.float32,
              out: wp.array(dtype=wp.float32)):
    i = wp.tid()
    wp.atomic_add(out, 0, a[i] * s)

x = wp.array(np.ones(8, dtype=np.float32), dtype=wp.float32, requires_grad=True)
y = wp.zeros(1, dtype=wp.float32, requires_grad=True)
tape = wp.Tape()
with tape:
    wp.launch(scale_sum, dim=8, inputs=[x, wp.float32(2.0), y])
tape.backward(y)
print(x.grad.numpy())  # each element should be 2.0

对可微仿真框架，该核对的是四项工程指标，比 star 数更能决定它能不能进训练管线：

  1. JIT 首次耗时与缓存命中率：控制环路里首次编译造成的长尾抖动是否可接受；
  2. 不连续算子的梯度可信度：接触、碰撞、 clamp 分支处的反传是否与物理直觉一致，需用有限差分逐点抽查；
  3. CUDA Graph 重放的适用边界：输入形状 / 控制流变化时图是否需要重建，重建开销多大；
  4. 跨框架互操作是否真的零拷贝：DLPack 路径在不同 PyTorch 版本与设备上的实际内存行为。
