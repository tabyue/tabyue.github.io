这个项目的定位很特别：它不是给机器人学习算法用的，而是给写代码控制机器人的 Agent 用的。随着 LLM Agent 在软件工程任务上逼近人类，「Agent 能不能控制物理系统」成了下一个自然的问题，但一直没有可比的评测床——各家自建环境和指标，结果无法横向比较。embodied-first-exam 的做法是把已有的机器人基准任务冻结成一套试题，规定答案形式为程序，然后在一个与答题环境隔离的沙箱里执行并判定，从而把评测变成标准化流程。

三层结构。①任务层：从多个公开机器人基准套件中选取任务并冻结参数（场景、物体、初始状态、成功判据），保证不同时间、不同 Agent 面对的是同一道题。②答题层：Agent 输出一段可执行的控制程序（而不是动作序列），程序在运行时读取观测、调用机器人能力接口、完成任务。③验证层：程序被送进独立沙箱执行，沙箱提供仿真或真机后端与统一成功判据，返回通过与失败原因。Harbor 作为承载平台，负责任务分发、沙箱生命周期与结果汇总。

  • RobotAgentBench: Towards Open-world Robot Autonomy — 开放世界机器人 Agent 基准，五维度评测（任务发现/情境推理/操作/失败恢复/鲁棒性）。
  • Sensorimotor Alignment — 免训练的离线代理指标，可在昂贵评测前筛模型。
  • Retrieve to Act — 测试时几何检索提升 VLA 分布外鲁棒性。

典型流程：准备 Harbor 运行环境并拉取任务集；把待测 Agent 接入「读取任务描述 → 输出程序」的接口；调用评测入口提交答案，平台在沙箱中跑程序并返回每个任务的通过与否与失败原因；汇总得到总分与各维度细分。最小验证是先跑一个已知答案的样例任务，确认沙箱与判据工作正常，再接入真实 Agent。

项目本身不报告 Agent 排行榜，其价值在于提供可复现的评测协议。可关注的指标是：任务通过率（总体与分套件）、程序首次通过率（反映 Agent 的一次成型能力）、以及失败类型分布（语法/接口错误 vs 语义/规划错误）。后者往往比总分更能指导改进方向。

与 RobotAgentBench（arXiv 2610.34649）相比：后者是家庭开放场景下的机器人 Agent 基准，强调任务发现与情境推理，场景丰富但搭建成本高；embodied-first-exam 更轻量、更标准化，答案是程序、验证在沙箱，适合快速比较不同代码 Agent。与 LIBERO / RoboTwin 这类操作基准相比：它们评测的是策略模型的成功率，不考察「自己决定做什么、把决策写成程序」的能力。三者是互补关系，分别对应策略、Agent、代码 Agent 三个层次。
