openrobokit/roboskills 是 OpenRoboKit 开源的一套「刻意做小」的机器人 Agent 工作流与工具集，MIT、Python，2026-10-30 创建、11-09 更新，约 200 star。

它不提供新模型，也不绑定某个本体，补的是模型与本体之间的连接层：遥操作数据采集、real2sim、动作生成、机器人仿真、任务编排，这些每个具身团队都要重写一遍的胶水代码，被收成一组可组合的最小工作流。topics 含 agentic-robotics、llm-agents、motion-generation、real2sim、robot-learning、robot-simulation。

与本轮 p416 TuringPAI（端侧模型怎么跑）、p414 ECHO（策略怎么按环境适应）配套：模型解决了 intelligence，工作流解决的是 repeatability——能不能把一次成功的实验原样再跑一遍、把数据原样再采一遍。

按仓库描述与同类工具集的一般结构，可归纳为四层（结构性归纳，具体以 README 为准）：

  1. 采集层：遥操作接口、 episode 记录与元数据（本体、任务、操作者、时间戳），输出符合机器人数据格式标准的轨迹。
  2. 转换层：real2sim / sim2real 的场景与本体映射，把真实采集的轨迹放进仿真器回放或生成对应仿真配置。
  3. 动作层：动作生成与技能编排，把高层任务描述拆成可执行的技能序列，供 Agent 调用。
  4. 执行与观测层：对接仿真或真实机器人，回传执行状态与成败信号，形成闭环。

「最小」二字是设计取舍：不内建训练框架、不内建大模型，因此不会和 SmolVLA / GR00T / LeRobot 这类生态抢位置，反而容易接进去。评估这类仓库的标准是接口是否稳定、元数据是否完整、失败是否可复现，而不是某个任务的成功率。

最小上手路径

git clone https://github.com/openrobokit/roboskills.git
cd roboskills
pip install -r requirements.txt
  1. 先读 README 的工作流清单，挑一条最短的：一次遥操作采集 → 存 episode → 仿真回放。
  2. 检查输出 episode 的元数据是否带齐本体型号、任务 ID、时间戳与操作者；缺了这些，后续数据闭环无法做 lineage。
  3. 把同一条 episode 在仿真里回放两次，比对末端轨迹是否一致——这是「可复现」的最低门槛。
  4. 接一个现成策略（如 SmolVLA 或 os320 DreamForge 生成的纠错样本），看工作流能否不改代码就换成另一个模型。
  5. 记录每个环节的耗时与失败点，判断瓶颈在采集、转换还是执行。

常见坑

  • 把工具集当成训练框架，期待它给出成功率提升；它的产出是可复现的流程与数据。
  • 不写元数据就存 episode，几周后无法追溯哪批数据来自哪个本体/标定版本。
  • 仿真回放通过就直接上真机，跳过频率、延迟与传感器噪声差异的检查。
