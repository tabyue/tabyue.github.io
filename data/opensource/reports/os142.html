项目概述

WBC-AGILE 是论文 AGILE: A Comprehensive Workflow for Humanoid Loco-Manipulation Learning 的官方实现，构建在 Isaac Lab 之上，提供一套端到端的人形全身移动操作（loco-manipulation）训练工作流。

「loco-manipulation」是人形机器人区别于机械臂的本质能力——边走边操作，或者说用同一个控制器同时解决「怎么站稳」和「怎么够到并操作物体」。这也是过去两年人形机器人最容易被 demo 掩盖真实水平的地方：行走是一套控制器、操作是另一套，拼接处就是失败高发区。

为什么这类工作流稀缺

训一个会走的人形-policy 已经有很多开源方案；训一个会抓的机械臂 policy 也有很多。但把两者合成一个同时决策的策略，涉及：

  • 特权信息（真机拿不到的物理量）怎么用
  • 奖励怎么设计才不打架
  • 怎么蒸馏成真机能跑的形式
  • 怎么验证真的能迁过去

AGILE 提供的是这条完整链路，而不是其中一环。

Teacher-Student 蒸馏：这条链路的核心

训练期（仿真）
┌────────────────────────────────────────┐
│  Teacher 策略                            │
│  输入：全部特权信息（真实摩擦、质心、外力…） │
│  输出：全身动作                            │
└───────────────┬────────────────────────┘
                │  行为克隆 / 蒸馏
                ▼
┌────────────────────────────────────────┐
│  Student 策略                            │
│  输入：仅真机可得的观测（关节角、IMU、视觉…）│
│  输出：全身动作                            │
└────────────────────────────────────────┘
部署期（真机）──► 只跑 Student

为什么必须蒸馏：仿真里可以白拿真实摩擦系数、精确质心、外部扰动力，真机上这些要么测不到、要么噪声大。让 Teacher 先用特权信息把任务学会（这样训练更稳、更快），再让 Student 只凭真机能拿到的观测量去模仿 Teacher——这是目前 sim-to-real 的主流范式。

关键细节：Student 的输入必须严格限制在真机可得的量上。一旦不小心把某个仿真专属量漏进 Student 的输入列表，训练指标会很好看，但一上真机就崩——这是最常见的 sim-to-real 事故。

统一评测指标

loco-manipulation 领域此前各家用各家的指标，导致论文之间无法比较。AGILE 提供一套统一指标，覆盖：

  • 移动质量（跟踪误差、能耗、稳定性）
  • 操作质量（成功率、精度）
  • 两者的耦合表现（边走边操作时的退化程度）

OSMO 分布式训练

NVIDIA 的作业编排工具，用于把大规模 RL 训练任务分发到多机多卡。对 loco-manipulation 这种样本需求量极大的任务，分布式训练不是可选项而是必需项。

前置条件：Isaac Lab + Isaac Sim。与 Arena 一样，NVIDIA 仿真栈是硬门槛。

建议的验证顺序：

  1. 先在仿真里跑通 Teacher。确认全身控制的任务能被学会，这是后续一切的基础
  2. 检查 Student 的观测列表。逐个确认每一项在真机上都能拿到、延迟可接受。这一步偷懒，后面全部白做
  3. 跑 sim-to-real 的最小验证：先在 G1 上做一个最简单的移动+抓取组合，别一上来就做复杂任务
  4. 用统一指标记录基线。先有一个可比较的数字，再开始改

真机注意事项

  • G1 与 Booster T1 的关节限位、扭矩带宽、通信延迟都不同，控制频率要按本体调
  • 蒸馏后的 Student 在真机上的第一次部署建议限速运行（降低增益），逐步提升
  • 全身控制的失败往往是耦合处而非单点：先分别验证「纯移动」与「纯操作」，再验证组合，能快速定位是哪一侧的问题

两个本体的验证意味着什么

G1 与 Booster T1 是结构差异不小的两款人形：尺寸、自由度配置、执行器方案都不同。在两者上都跑通，说明这套工作流的本体适配部分是通用的，而不是对某一款硬件过拟合。

但仍然要打折：两款都是中小型双足人形。对全尺寸（1.6m+）人形，动力学特性（惯量、柔性、地面冲击）差别很大，不能直接套用。

与其他人形控制方案的定位

方案 覆盖 sim-to-real 许可
WBC-AGILE 移动 + 操作耦合 G1 / T1 已验证 NVIDIA 源码许可
纯 locomotion 开源方案（如各校 RL 行走代码） 仅移动 多数有 多为 MIT/Apache
纯 manipulation 方案 仅操作（固定基座） 多数有 多为 MIT/Apache
商业全身控制栈 全身 有但不公开 闭源

AGILE 的独特价值就在「耦合」二字。行走与操作各自的开源方案都很成熟，难的是合起来——而这正是人形机器人真正需要的能力。
