长时程为什么会断

典型 VLA 的输入是固定长度的观测窗口：

$$ a_t = \pi(o_{t-K:t},\, \ell) $$

当任务跨度超过 $K$ 帧所覆盖的时间，模型在物理上就看不到早期证据。常见缓解手段有三种，都有代价：

做法 代价
直接加大 $K$ 计算与显存随 $K$ 增长，且注意力被稀释
把历史压成文本摘要 丢掉精确的空间与接触信息
外挂检索式记忆 检索什么、什么时候检索都要额外设计

SimpleMemVLA 走的是第四条路：历史就是视频，原样保留，但用流式推理把成本压下来。

与 SimpleNav 的关系

同属 OpenBMB 的 Simple 系列，思路一致——把一个方向里「大家都各写各的」的部分抽成统一框架。SimpleNav 做导航 VLA，SimpleMemVLA 做记忆。

三个关键组件

  1. 时间戳视觉历史：历史帧不是堆在一起，而是带上时间戳组织成视频记忆，让模型知道「这一步发生在多久以前」。
  2. 精确流式推理：新帧到来时复用已有帧的 KV 缓存，只对新帧做完整计算。所谓「精确」是指不牺牲注意力覆盖范围——与常见的滑窗丢弃不同。
  3. 记忆读写策略：决定保留哪些帧、什么时候淘汰。

为什么「精确」很重要

很多长上下文方案是近似的（滑窗、压缩、稀疏注意力）。在机器人操作里近似有具体后果：你不确定模型到底有没有看到那次失败的关键帧。精确流式推理保证「历史全在，只是算得快」。

使用要点

from simplememvla import MemVLA, VideoMemory

model = MemVLA.from_pretrained('OpenBMB/SimpleMemVLA')
memory = VideoMemory(max_seconds=120, fps=4)   # 保留 2 分钟视觉历史

for obs in stream:
    memory.append(obs.rgb, t=obs.timestamp)
    action = model.act(obs, memory, instruction)

上手建议

  1. 先在一个短任务上跑通，确认不带记忆时基线正常；
  2. 人为构造一个需要长记忆的任务（比如「把 A 放到 X，再把 B 放到 A 旁边」，且两步之间插入 30 秒的其他动作）；
  3. 对比开 / 关记忆的成功率——这个差距就是记忆模块的真实价值；
  4. 再逐步拉长间隔，找到你的任务在哪个时间跨度上开始崩。

怎么评估它

不要只看官方数字。对你自己的任务，最有说服力的是记忆跨度—成功率曲线：横轴是任务中「需要回忆的证据距现在多少秒」，纵轴是成功率。开记忆前后两条曲线之间的面积，就是这个模块给你的真实收益。

方案 历史保真度 推理成本 适用场景
加大观测窗口 高 随 $K$ 线性增长 跨度 < 数十帧
文本摘要 低（丢空间细节） 低 语义级长期记忆
检索式外挂记忆 中 取决于检索 需要精确定位历史片段
SimpleMemVLA 视频记忆 高（原样保留） 流式复用，可控 需要精确视觉证据的长时程操作

选型判据：如果你的失败是「模型不记得它刚才做过什么动作」，用视频记忆；如果是「模型不知道三小时前这间屋里有什么」，那更像 LT-Mem 那类跨 session 长期记忆问题（见本期论文 p266），不是同一个尺度。
