为什么需要 EasyWAM

世界动作模型在 2026 年进入快速涌现期：DreamZero、Cosmos Policy、Fast-WAM、FLUX 3 Action、OpenWAM、ModAR……但每家都换了视频骨干、训练数据、视频与动作的交互方式和推理流程。

结果是：你看到某家涨了 5 个点，但说不清是哪个设计带来的。对研究者这妨碍归因，对工程师这妨碍选型。

EasyWAM 的思路是提供一个公共底座：把骨干、数据、交互方式、评测做成可替换的模块，让大家在同一套脚手架上做对照实验。

它不是什么

EasyWAM 不提出新模型，也不承诺 SOTA。它的产出是可复现性与可比的实验条件。这在一个指标通胀、归因混乱的领域里，价值不比一个新模型低。

流水线分层

数据处理 → 模型组件（骨干 / 交互方式 / 动作头）→ 分布式训练 → 评测
     ↑                    ↑                        ↑          ↑
  统一接口            可替换模块              LoRA / 全参   统一 benchmark

为什么「效率是一等公民」很重要

WAM 的训练成本显著高于普通 VLA——它要同时建模未来观测与动作，序列更长、模态更多。如果效率靠事后优化，多数研究者跑不起对照实验，框架也就失去了「提供可比条件」的意义。

  • DreamZero — NVIDIA 提出 WAM 术语的代表工作，是 EasyWAM 需要兼容的主要模型形式之一。
  • ModAR: Modality-Autoregressive World-Action Models — CMU 的模态自回归 WAM，展示了 EasyWAM 需要支持的模态组合维度。
  • OpenWAM: An Open Framework for Composable World-Action Models — 斯坦福的可组合 WAM 框架，与 EasyWAM 目标相近、实现方式不同。
  • FLUX 3 Action — Black Forest Labs 的开源 7B WAM，可作为 EasyWAM 的骨干候选。
  • Think Like a World Model, Act Like a VLA — 把 WAM 表征蒸馏进紧凑 VLA，是 WAM 落地路径的重要补充。

框架定位

EasyWAM 本身不发布性能数字，它提供的是跑出可比数字的脚手架。具体的基准结果见仓库文档中的 Benchmark Results 部分与 HuggingFace 上各 checkpoint 的模型卡。

框架 目标模型族 是否做训练 特色
EasyWAM 世界动作模型（WAM） 是 模块化 + 效率优先，专为 WAM 归因设计

OpenWAM WAM 是（官方实现） 单个模型族的官方代码

EasyWAM 与 OpenWAM 都面向 WAM，但前者是多模型的统一底座，后者是单个模型的官方实现。要做跨模型对照选 EasyWAM；要复现 OpenWAM 自身结果则用其官方仓库。

与 XPolicyLab 是互补关系：EasyWAM 负责把模型训出来，XPolicyLab 负责把训好的模型公平地接到评测上。
