人形全身控制（whole-body control）的难点在于自由度多、接触状态频繁切换，而且 locomotion 与 manipulation 往往要共享同一套躯干与平衡约束。传统做法按任务切分策略：走路一套、抓取一套、起身一套，切换时容易出现姿态跳变或平衡失守。

HoloMotion 把「全身运动控制」按基础模型的思路组织：用统一表征覆盖多任务，让上层只给目标，不必操心底层怎么维持平衡。这是地平线机器人在具身基座模型方向上的开源动作，对做「上层 VLA + 下层 WBC」分层架构的团队尤其有参考价值——下层接口是否稳定，直接决定上层策略能不能只学任务语义。

按基础模型类项目的常见分层推断，可理解为：

  1. 输入层：本体状态（关节角、IMU、接触）、任务指令或参考运动。
  2. 统一表征层：把不同任务映射到共享的状态—动作潜空间，这是「基础」二字的落点。
  3. 控制层：输出全身关节目标（位置 / 力矩），兼顾平衡与接触约束。
  4. 部署层：推理运行时、模型导出与本体适配配置。

分层架构里它站在哪一层，本站多个模块都讨论过「整体式 VLA vs 分层」的取舍。HoloMotion 属于分层里的执行底座：上层负责理解与规划，它负责把意图变成稳定、连续的全身动作。这种分工的好处是上层换任务不用重训底层，代价是接口设计要非常克制。

  2. 用仓库提供的权重 / 推理路径先跑通一个任务：不要一上来复现训练，基础模型类工作的训练数据与算力门槛不低。
  3. 验证多任务切换是否平滑：这是它相对「按任务切策略」的核心卖点，重点看切换瞬间的姿态与力矩有没有跳变。
  4. 再考虑接上层 VLA / Agent：把动作接口契约（指令格式、频率、超时与兜底）写清楚再对接，避免上层把底层当黑盒乱调。
  5. 最后才做二次训练：确认基线可复现、评测脚本能跑通，再动训练配置。

评估全身控制基础模型，建议看四类指标而非单一成功率：

  • 多任务覆盖度：同一套权重能稳定跑多少类任务。
  • 切换平滑度：任务切换瞬间的关节力矩突变、姿态跳变幅度。
  • 扰动恢复：受推、打滑、负载变化后的回稳时间与失败率。
  • 部署成本：控制频率、推理延迟、单卡能否实时。

注意区分「跟踪精度」与「任务成功率」：运动跟踪误差小不代表能完成操作任务；反过来，任务成功也可能掩盖了不平滑的动作。两者都要报。

sim-to-real 落差在全身控制上尤其显著，真机摩擦、本体柔性、关节温升都会在长时运行时暴露出来，评测务必包含连续运行时长。

对比按任务切分的 WBC 策略：后者在单一任务上可以调得很精，但切换逻辑要手写、易出跳变；HoloMotion 追求统一表征覆盖面，代价是单任务极限性能可能不占优。

对比 TienKung-Lab / cyclotron 一类 IsaacLab 训练框架（本站 os206 / os233）：那些是训练脚手架，帮你从零搭 RL 管线；HoloMotion 是模型 / 基座，给的是可直接推理的控制能力。一个解决「怎么训」，一个解决「用什么」。

对比 ∇Mimic 等一阶可微仿真方法：可微仿真走的是用解析梯度高效求策略的路线，HoloMotion 走的是大规模预训练统一表征路线，二者是不同技术栈，可在同一评测任务上做对照。
