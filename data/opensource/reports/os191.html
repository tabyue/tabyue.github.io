GroundingPI 解决的是一个被长期低估的问题：机器人需要的「定位」和通用 VLM 提供的「定位」不是一回事。

三类定位的区别

任务 问的问题 典型使用者
检测 图里有哪些物体、在哪 通用视觉
指称（referring） 「红色马克杯」在哪 通用 VLM
指向（pointing） 我该接触哪个点 机器人

通用 VLM 在第二类上已经很强，但第三类——可操作点（affordance-aware point）——仍然薄弱。典型失败：模型正确识别了「红色马克杯」，却把点给到杯身而不是把手；或者遮挡下把指代漂移到同类的另一个物体上。

为什么要把 grounding 做成独立基座

方案 A：在 VLA 内部做端到端 grounding。 代价是占用骨干网络容量、难以单独评测、无法复用社区进步。

方案 B（GroundingPI 的取向）：外挂专用 grounding 基座。 输出结构化坐标 + 置信度，交给策略层消费。好处是： - grounding 能力可以独立迭代与评测； - 同一个模型服务多个策略； - 4B 规模可以在边缘侧部署，不占机器人主控的算力预算。

六类任务统一的价值

检测 / 指代 / 指向 / OCR / GUI / 版面看似分散，但在机器人场景里是同一件事的不同侧面：

  • 看到操作台上的说明书 → OCR；
  • 听到「把蓝色那个拿过来」 → 指称；
  • 决定夹爪落点 → 指向；
  • 看懂屏幕上的界面 → GUI；
  • 理解表格与面板布局 → 版面；
  • 常规物体定位 → 检测。

统一到一个模型意味着一次前向解决全部，也避免了多模型串联时的误差累积与延迟叠加。

关键设计决策

1. 任务区分靠 prompt 而非多套头。 六类任务共用一套权重，通过指令或特殊 token 切换。这让模型可以在任务之间共享表征——OCR 学到的文字定位能力会帮助 GUI grounding，检测学到的物体边界会帮助指向。

2. 指向（pointing）是具身化的关键一环。 它输出的不是框而是点，直接对应「末端执行器该去哪」。这一步把 grounding 从「理解」推进到「可操作」。

3. 置信度必须随坐标一起输出。 策略层需要它在置信度低时切换到主动感知分支（换个视角再看一眼），而不是硬着头皮执行。

4. 4B 规模的取舍。 相比 7B—70B 的通用 VLM，4B 明显更轻，可以在机器人本机的边缘算力上跑；代价是在复杂语义推理上不如大模型，因此定位是「专用工具」而非「通用大脑」。

  • AffordanceVLA: Empowering Action Generation through Affordance-Aware Understanding — 在 VLA 里显式引入可供性理解，与 GroundingPI 的外挂路线形成对照。
  • Grounded Action Model: 3D Grounding as a Foundation for Robotics — 把 3D grounding 作为机器人能力的基础层。
  • GiT（Grounded in Time） — 面向感知歧义下时序定位的双臂操作数据集与基准。
  • Galahad — 反事实指令跟随基准：改一个词、场景不变，记录机械臂抓向哪个物体，是评测 grounding 模块的实用工具。
  • Causal Analysis of Robot Foundation Models — 用激活补丁定位 VLA 里「选哪个物体」与「往哪去」的计算位置，可与外挂 grounding 方案互为验证。

建议的接入流程

Step 1：先单独评测，再接入策略。 不要直接把 grounding 接进 VLA 然后看端到端成功率——那样无法归因。先做一组反事实指令测试：

"把左边的红色杯子拿起来"   vs   "把右边的红色杯子拿起来"
"抓住马克杯的把手"         vs   "抓住马克杯的杯身"

只改一个词、场景不变，记录输出点是否随之正确变化。这比平均 AP 更能暴露指代漂移。

Step 2：把坐标 + 置信度一起传下去。

# 伪代码：grounding -> 策略层
result = grounding_pi(image, instruction)
# result = {boxes: [...], points: [...], scores: [...], task_type: 'pointing'}

if result.scores[0] < TAU:          # 置信度不足
    obs = move_camera_and_reobserve()   # 主动感知：换视角再看
    result = grounding_pi(obs, instruction)

action = policy(result.points[0], obs)

Step 3：处理坐标系与帧率。 grounding 通常跑在相机帧率（如 30 Hz）上，动作 chunk 在控制帧率（如 10—50 Hz）上。两者之间的时间对齐与坐标系变换是集成阶段最容易出错的地方，务必写单元测试。

  • 34 个基准整体 SOTA（据仓库说明）：覆盖检测、指代、指向、OCR、GUI、版面六类；
  • 受控评测中提升机器人泛化与数据效率：这是机器人团队最关心的两项——泛化意味着换场景不崩，数据效率意味着少采数据；

需要注意的限制

  • 通用语义推理能力弱于大模型：4B 规模决定了它适合做「专用工具」，复杂指令理解仍需上层大模型；
  • SOTA 的说法需自行核验：34 个基准的构成与对比方法需在论文/项目主页确认；
  • 「提升机器人泛化与数据效率」是受控评测结论：需确认任务规模与对比基线；
  • 指向点的精度与接触姿态无关：它给点不给姿态，六自由度抓取姿态仍需额外的可供性/姿态估计模块。

一句话选择：要一个可独立评测、可复用、可边缘部署的具身定位模块 → GroundingPI；要端到端最省事 → VLA 内置；要通用图文理解 → 通用 VLM。

实践建议：三者不必互斥。常见组合是「上层大模型做指令理解 → GroundingPI 做定位 → VLA 做动作生成」，把各自的强项串起来。
