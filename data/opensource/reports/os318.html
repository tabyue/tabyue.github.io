Yanshi-Robotics/nerv 是言识机器人开放的 NERV — a nervous system for robots: a language-model brain, a robot body and a world, coupled by one platform。仓库 2026-09 创建、2026-11-22 仍在更新，Python、MIT，约 100 star。

它不做单点算法，而是把三件事的连接做成统一平台：语言模型当大脑、本体当身体、仿真或真实环境当世界，让具身 Agent 的感知、决策与执行在同一套接口里闭环。「神经系统」这个比喻是准确的——价值在连接与协议，而不在某一个模型有多强。

与本轮新增内容形成上下游：p411 AgentRoboCritic 做动作级评判、n806 Mind2Act World 做诊断式基准，判断的是「Agent 接进机器人之后每一步做得对不对」；NERV 负责先把 Agent 接进去。MIT 许可与活跃更新适合作为 /learn/embodied-agent 与 /learn/ros2 的实验底座。

按仓库描述与 Agent 原生机器人平台的一般结构，可归纳为四层（结构性归纳，具体以 README 为准）：

  1. 脑层（Brain）：语言模型 / 多模态模型负责目标分解、长程规划与工具选择，输出结构化意图或技能调用。
  2. 体层（Body）：机器人本体的关节、传感器与控制器，向上提供状态、向下接收动作。
  3. 世界层（World）：仿真器或真实环境，提供观测反馈与任务成败信号。
  4. 耦合层（Coupling）：三者之间的消息协议、时钟与频率匹配，以及失败回传通道——这是「一个平台」真正的含义。

第 4 层最容易被低估。脑层按秒级思考、体层按毫秒级控制、世界层按帧级推进，三者频率不同步时，再好的规划也会在接口处失真。站内 /learn/ros2 的「把 1 kHz 运控与 50 Hz 策略放进同一台机器」一章，讲的正是这类分层与频率治理。

最小上手路径

  1. 打开 https://github.com/Yanshi-Robotics/nerv ，先读 README 的架构图与依赖说明，确认支持的本体与仿真器。
  2. 按 README 建环境（Python，MIT）：
git clone https://github.com/Yanshi-Robotics/nerv.git
cd nerv
pip install -r requirements.txt
  1. 先用仿真世界跑通一条最小任务：语言指令 → 脑层分解 → 体层执行 → 世界反馈 → 脑层收到结果。先验证闭环通，再谈成功率。
  2. 记录三层的频率与延迟：脑层决策间隔、控制周期、观测帧率，画一条时间线找瓶颈。
  3. 接评测：把 p411 AgentRoboCritic 的动作级评判思路接进来，让每个动作附带局部意图，失败时回传到脑层做恢复。

常见坑

  • 只调语言模型 prompt，不查耦合层的时钟与丢帧，会把接口问题误判成模型能力问题。
  • 仿真里跑通就直接上真机，忽略频率与延迟差异。
  • 不做失败回传通道，Agent 无法形成闭环恢复能力。
