解决的两个真实痛点

痛点一：失败自愈的训练成本极高

为了让机器人学会失败自愈（Recovery），通常需要采集大量失败数据并重新微调大模型。采集失败数据这件事本身就反直觉——你要故意让机器人反复失败，成本高风险大。

痛点二：串行延迟劝退

让前沿 VLM（GPT-4o、Qwen 等）逐步规划动作，机械臂会走一秒停两秒。物理落地不现实，API 费用也在飞速燃烧。

Spotter 的思路：外挂监视

它颠覆了「大模型指哪、小模型打哪」的传统链条，把系统分成两个异构流：

流 角色 频率 成本
System 1（小脑） 具身策略模型（π0.5、Cosmos Policy 等）全程掌控机械臂轨迹 高频、连续 低
System 2（大脑） 前沿 VLM（GPT-4o / Qwen-VL）在后台异步监控 只在异常时介入 高但极少调用

关键机制是一个轻量级筛查器：只有它捕获到连续异常（Double-check）时，VLM 才介入执行长上下文反思与轨迹纠偏。

三个核心卖点

  1. Training-free：不需要重训具身模型，也不需要训练失败反思数据
  2. Plug-and-play：现成的具身策略（π0.5、Cosmos Policy 等）直接接入
  3. 极低调用开销：整体耗时降低约 70%

一句话总结

别再让大模型指导微操了。让小模型连续跑，大模型只在出问题时回头看一眼。

为什么异步是关键

同步方案（VLM 逐步规划）的耗时结构是：

T_总 = N_steps × (T_观测 + T_VLM推理 + T_执行)

VLM 推理通常数百毫秒到数秒，直接乘上步数，任务时长完全不可接受。

异步方案把 VLM 移出关键路径：

T_总 ≈ N_steps × T_执行 + K × T_VLM推理     （K ≪ N_steps，K 为触发次数）

VLM 的延迟不再累加到每一步上，只在真正需要时被支付。这就是「整体耗时降低约 70%」的来源。

Double-check 机制为什么重要

单帧异常检测会大量误报——光照突变、遮挡、轻微抖动都会被判为异常。如果每次误报都调用 VLM，成本立刻回去。

连续异常才触发（Double-check）是一个极简但有效的滤波：

if anomaly_signal and prev_anomaly_signal:
    trigger_vlm_reflection()

这条规则把「瞬时噪声」与「真的卡住了」区分开。实现成本几乎为零，但直接决定了这个架构能不能省钱。

与传统分层架构的区别

传统分层是 规划 → 执行 的单向链条，大模型在上面，小模型在下面，每次执行前都要等规划。

Spotter 是 执行为主 + 巡检为辅，控制权的默认归属是小模型。大模型没有「指挥权」，只有「异议权」。这个权力关系的反转是它与传统架构最本质的区别。

免训练是怎么做到的

关键在于：VLM 的反思能力来自它自己的预训练，不需要针对失败数据微调。Spotter 只是把「机器人刚才做了什么、现在看到什么」组织成 VLM 能理解的上下文，让它自己判断哪里出了问题、该怎么改。

这意味着接入一个新的具身策略不需要任何训练——只要策略能输出动作、能拿到观测，就能接。

概念性最小示例

以下为结构示意，具体 API 以仓库为准：

from spotter import Spotter, AnomalyDetector

# 1. 接入你已有的具身策略（无需重训）
policy = load_your_policy('pi0.5')     # 或 Cosmos Policy 等

# 2. 外挂一个轻量筛查器 + 前沿 VLM
spotter = Spotter(
    policy=policy,
    detector=AnomalyDetector(window=5, threshold=0.6),
    vlm='gpt-4o',                      # 也可换 Qwen-VL
)

# 3. 正常跑你的任务，Spotter 在后台异步巡检
obs = env.reset()
while not done:
    action = spotter.step(obs)         # 默认走小模型，异常时自动纠偏
    obs, done = env.step(action)

关键实践提醒

先跑通不带 Spotter 的基线。Spotter 是外挂层，如果基线策略本身跑不通，外挂也救不了。先确认基线的失败模式是「偶发卡住」而不是「系统性不会做」——只有前者适合用反思纠偏来救。

调参优先级

  1. 筛查窗口（window）：太小会误触发，太大会漏掉真实异常。建议从 5 帧开始
  2. 异常阈值（threshold）：影响触发频率，直接决定 VLM 调用成本
  3. VLM 选择：本地 Qwen-VL 便宜但能力弱，GPT-4o 强但贵。按失败模式的复杂度选

常见坑

  • 把 VLM 用在精细动作生成上：这是 Spotter 明确反对的用法。VLM 只做反思与纠偏规划，具体动作仍由小模型输出
  • 忽略触发日志：如果触发频率远高于预期，先查筛查器阈值，而不是急着换更强的 VLM
  • 网络延迟：异步不代表无延迟，VLM 调用若在主进程内同步等待，收益会消失

如何解读「耗时降低 70%」

这个数字的比较基准是同步 VLM 逐步规划方案，而不是纯小模型基线。也就是说：

  • 对比纯小模型：Spotter 会增加一些耗时（VLM 异步调用的开销）
  • 对比同步 VLM 规划：Spotter 省掉约 70%

正确的理解是：Spotter 用很小的额外开销，换来了接近大模型的纠偏能力。如果你的基线本来就是纯小模型且不需要纠偏，Spotter 反而会变慢。

真正的收益在哪

最值得关注的其实不是 70%，而是免训练这一条：

  • 采集失败数据需要故意让机器人反复失败，成本高风险大
  • 重训大模型需要算力与时间
  • Spotter 两者都省掉了

对一个已经训好策略、只想提高鲁棒性的团队，这个「零训练成本」比耗时数字更有吸引力。

怎么选

  • 失败模式可枚举、可采集 → 失败数据微调效果更稳，但需要训练成本
  • 失败模式开放、无法预先枚举 → Spotter 更合适，VLM 的零样本泛化能覆盖未见过的失败
  • 对延迟极度敏感且失败率低 → 纯小模型，外挂层的开销不值得

Spotter 的边界

它不能做什么：

  1. 不能提升基线策略本身的能力——如果策略根本不会做这个任务，反思纠偏救不了
  2. 不能处理 VLM 看不懂的失败——例如力控偏差、关节超限，纯视觉 VLM 很难判断
  3. 不能消除所有延迟——异步只是移出关键路径，VLM 调用本身仍需时间

它擅长什么：

  1. 偶发性卡住（抓取滑脱、物体被挡、动作序列走偏）
  2. 失败模式无法预先枚举的开放场景
  3. 已有可用策略、只想加一层保险的情况

与 RPent（os146）的关系

两者不冲突，层次不同：

  • RPent 是系统级编排框架，定义失败恢复应该放在哪一层
  • Spotter 是一个具体的免训练恢复策略，可以作为 RPent 的 Harness 层里的一个实现

换句话说，如果你已经用了 RPent，Spotter 是「失败恢复」这一格里可以填入的一个现成答案。
