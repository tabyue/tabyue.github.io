项目概述

Qwen-VLA 是阿里通义实验室 2026-05-29 开源的具身基础模型，核心主张是「一个模型同时干三件事、同时管十一种身体」：

  • 三大任务统一：桌面 / 双臂操作、视觉语言导航、末端轨迹预测共享同一套权重，不再是「操作一个模型、导航另一个模型」
  • 十一种本体统一：从单臂 Franka 到 ALOHA 双臂、从轮式底盘到人形，硬件差异不靠换 head，而是编码进 prompt

一句话定位：Qwen-VLA 是国产阵营对 π₀.₅ / GR00T 这类「通用具身基座」路线的正面回应，也是首个把「跨任务 + 跨本体」两个维度同时打通并完整开源（Apache-2.0）的中文团队工作。

技术报告：arXiv:2605.30280

Embodiment-Aware Prompt Conditioning

这是全模型最关键、也最反直觉的一个设计：把硬件差异当成语言问题处理。

传统跨本体方案要么给每个本体单独一个 action head（参数随本体数线性增长、新本体必须重训），要么把所有动作空间 padding 到同一个最大维度（浪费容量、语义混乱）。Qwen-VLA 改为把「几条手臂、多少自由度、绝对还是增量控制、控制频率多少」写成自然语言，和任务指令一起送进 VLM：

[Task]        put the mug into the microwave and close the door
[Embodiment]  single-arm Franka Panda, 7-DoF joint position,
              delta control, 20Hz, parallel gripper

带来的三个直接好处：

  1. 参数不随本体数增长 —— 11 种本体共用一套 DiT 解码器
  2. 新本体零架构改动 —— 只要能用语言描述清楚，就能加入训练或直接尝试零样本迁移
  3. VLM 的语言先验被复用 —— 'dual-arm' 与 'two arms' 天然语义接近，本体之间因此可以共享泛化

四阶段训练流程

Qwen-VLA 的训练被拆成 T2A → CPT → SFT → RL 四段，每段解决一个特定问题：

阶段 全称 目标 关键做法
T2A Text-to-Action 让 VLM 先学会「动作是一种可生成的模态」 用文本 / 轨迹配对数据对齐语义空间与动作空间
CPT Continual Pre-Training 大规模跨本体跨任务预训练 混合 11 种本体的操作 / 导航 / 轨迹数据联合训练
SFT Supervised Fine-Tuning 下游任务对齐 在目标本体 / 目标任务的高质量演示上精调
RL Reinforcement Learning 补齐模仿学习吃不到的长尾 在仿真中做在线试错，修复分布外与长程失败模式

为什么必须有 RL 阶段

纯模仿学习的策略在演示覆盖不到的状态上会迅速退化——这正是 OOD 评测掉分的主因。Qwen-VLA 最亮眼的一组数字（ALOHA OOD 76.9%，相对 π₀.₅ 提升 35.4 个百分点）主要来自这一阶段：RL 让策略在「已经偏离演示分布」的状态下依然知道怎么把任务拉回正轨。

与 DiT 动作头的配合

动作解码器采用 DiT 而非自回归 token 预测，好处是动作 chunk 整段生成、时序更平滑，坏处是采样步数带来延迟。工程上通常配合减少去噪步数 + 动作 chunk 复用来把控制频率拉到可用区间——这一权衡与 os104 FASTER（流匹配 VLA 单步快采样）关注的是同一个瓶颈。

推理：关键在于写对 Embodiment Prompt

from qwen_vla import QwenVLAPolicy

policy = QwenVLAPolicy.from_pretrained('./checkpoints/qwen-vla')

# 本体描述写得越准，跨本体迁移效果越稳
embodiment = (
    'single-arm Franka Panda, 7-DoF joint position, '
    'delta control, 20Hz, parallel gripper'
)

obs = {
    'images': {'head': head_rgb, 'wrist': wrist_rgb},
    'state': joint_positions,
}

action_chunk = policy.act(
    obs,
    instruction='pick up the red cube and place it on the plate',
    embodiment=embodiment,
)
# action_chunk: (chunk_size, action_dim)，维度由 embodiment 决定

迁移到自己的机器人

1. 先用自然语言把本体写清楚：几条臂 / 多少 DoF / 绝对还是增量 / 控制频率 / 末端形式
2. 直接零样本跑一遍，记录失败模式（抓不准？抖动？语义理解错？）
3. 抖动多 → 检查控制频率与 chunk 长度是否匹配
4. 语义对但动作偏 → 采 50-200 条演示做 SFT
5. 只在特定场景失败 → 该场景做 RL 微调，而不是盲目加演示

常见坑

  • Embodiment Prompt 与真实控制接口不一致（写了 delta 实际发绝对值）会导致动作看似合理但执行发散，这是最高频的接入错误
  • 多视角相机命名要和训练时保持一致，视角错位比图像质量差影响更大
  • DiT 去噪步数直接决定单次推理耗时，真机部署前先量一遍端到端延迟

两个数字值得单独说

① ALOHA OOD +35.4pp —— OOD 是当前 VLA 落地的真实瓶颈：实验室 95% 成功率的策略进到没见过的光照 / 摆位 / 干扰物场景常常腰斩。这个提升幅度说明「四阶段训练 + RL 收尾」对分布外鲁棒性的贡献远大于继续堆演示数据。

② DOMINO 零样本反超微调基线 —— Qwen-VLA 没在 DOMINO 上训练，却超过了专门在 DOMINO 数据上微调的 PUMA（见 os088）。这是「通用基座 + 足够多样的预训练」压过「小数据专用微调」的一个直接证据。
