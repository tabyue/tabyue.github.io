一个被长期忽略的问题：证据不够时怎么办

现有多传感器机器人系统的主流做法是融合——视觉、听觉、触觉、力觉各出一份特征，拼起来做推断。这套范式隐含一个前提：现有观测已经包含了回答问题所需的全部信息。

现实里这个前提经常不成立。用户说「帮我找个杯子装点茶」，机器人需要：

  1. 理解隐含意图——要的是空的杯子；
  2. 判断哪个候选是空的；
  3. 而「空不空」这件事，光看是看不出来的。

人会怎么做？摇一摇、掂一掂。ROMA 要赋予机器人的正是这种能力。

系统的两个组成部分

  1. LLM 推理核心：判断证据是否充分；不足时输出三元组——目标物体、交互动作、模态。
  2. 物理接口：执行交互，采集多模态反馈，回填给推理核心。

由此形成 perception chain（感知链）：每一步的「思考」是证据充分性判断，每一步的「行动」是一次物理交互，终止条件是证据充分。

数据：ROMI-2K

  • 近 2000 个真实物体
  • 6 类原子交互（掂、摇、捏、敲等）
  • 视觉 / 听觉 / 触觉 / 力觉同步采集
  • 托管在 HuggingFace：GeWuLab/ROMA

同步性是数据集的核心价值。多模态数据若时间不同步，模型学到的会是虚假关联——例如把「物体被拿起时刻的力矩跳变」错配到「摇动产生的声音」上，因为两者时间戳相邻。主动感知依赖对交互—反馈因果关系的正确建模，同步错误会直接摧毁这一基础。

两阶段训练

阶段一：跨模态对齐

四个模态的信号统计特性差异极大：

模态 形态 特点
视觉 高维空间网格 稠密、冗余度高
听觉 时序频谱 高频、短时
触觉 低维阵列 稀疏、仅在接触时激活
力觉 六维向量 低频、与动力学强相关

先做对齐，让它们进入可比较的表示空间。若这一步没做好，后续模型会倾向于只使用信息最「好用」的模态（通常是视觉），其余模态形同虚设。

阶段二：能力注入

训练 LLM 学会三件事：

  1. 评估证据充分性——现在能不能答了；
  2. 选择信息量最大的交互——下一步该做什么；
  3. 在多模态反馈上推理——拿到了怎么更新判断。

为什么模态选择必须可学习

「摇一摇听声音」和「捏一捏试硬度」对同一问题（杯子空不空）的信息增益不同。固定流程（先视觉、再触觉、再力觉）会在大量任务上浪费交互预算。

用信息论的语言，理想选择应当最大化关于目标属性的条件互信息 $I(Y; F_i \mid E_t)$。关键在于这个量依赖于当前证据 $E_t$：同一次「摇一摇」，在已知物体是实心时信息增益接近零，未知时却很高。因此交互选择必须是状态依赖的函数——这正是需要用 LLM 近似的部分。

与贝叶斯实验设计的联系

上述贪心互信息准则就是贝叶斯实验设计中的经典策略。ROMA 的贡献不是提出准则，而是：

  1. 把它放进真实物理系统，让「实验」真的是摇一摇、捏一捏；
  2. 用 LLM 近似 $i_t^*$，绕开了对后验 $p(Y \mid E_t)$ 显式建模的需求；
  3. 提供数据让这个近似可被训练与评测。

理解这一点很重要：LLM 不是在背答案，而是在近似一个本应由贝叶斯后验给出的决策量。

最小验证：先只做单属性任务

不要一上来就跑长链。先验证一件事：模型能否为单个待定属性选对交互与模态。

from roma import PerceptionChain, SensorSuite

chain = PerceptionChain.from_pretrained('romi-base')
sensors = SensorSuite(vision=..., audio=..., tactile=..., force=...)

# 单属性：这个杯子是空的吗
answer = chain.run('这个杯子是空的吗', max_steps=3)
print(answer)   # 期望：'empty' / 'not_empty' / 'insufficient_evidence'

若这一步都不稳定，长链一定跑不通。

主循环实现要点

class PerceptionChain:
    def run(self, query, max_steps=8):
        '''
        最多交互 max_steps 次；超出即判定「证据无法充分」。
        在物理系统上，错误的确定答案比「不知道」更危险。
        '''
        for _ in range(max_steps):
            decision, answer = self.step(query)
            if answer is not None:
                return answer
        return 'insufficient_evidence'

三个必须做的工程保护：

  1. 证据充分性判断要有显式阈值——不能让模型一直觉得「还不够」，否则长链任务会无限交互；
  2. 交互预算要设上限——超限时输出「无法确定」而不是硬猜；
  3. 模态选择要记录日志——用于分析信息增益；若某模态长期不被选中，检查对齐阶段是否没做好。

自建数据采集时的硬性要求

如果要用自己的硬件采集类似数据，同步是最容易翻车的一环：

  • 用硬件触发而非软件时间戳。多进程采集下软件时间戳漂移可达数十毫秒，足以破坏「摇动—声音」的因果配对；
  • 触觉与力觉的采样率通常远高于视觉，需明确降采样或标注对齐策略；
  • 采集后回放检查：把一次交互的四个模态画在同一时间轴上，肉眼确认因果关系正确。

调试顺序

  1. 先确认数据同步正确（回放检查）；
  2. 再确认单属性任务的交互选择正确；
  3. 然后放开长链，观察每一步的证据充分性判断；
  4. 最后测意图驱动类任务——这一类需要模型自己推导「需要哪些属性」，是能力的真正检验点。

论文报告的结论

ROMA 能主动获取缺失证据，解决现有方法难以处理的复杂长链多感官感知任务。

如何正确理解「现有方法难以处理」

这句话需要准确解读：不是现有方法精度低，而是任务设定超出了它们的能力边界。被动融合系统没有「再交互一次」这个动作空间，遇到单靠观察无法判断的属性（例如密封盒子里的物体数量），只能输出一个答案，无论对错。

ROMA 的优势来自可扩展的动作空间，而不是更强的推理能力。区分这两点很重要——如果把收益误归因于推理，会高估方法在「观察即可回答」类任务上的表现。

评测设计带来的可诊断性

ROMA Bench 的三类任务其实构成一个诊断梯度：

类别 若失败，问题可能在哪
单属性 交互/模态选择错误，或跨模态对齐不足
长链多属性 证据累积或终止判断有问题
意图驱动 从意图到属性的推导链条断了

在自己的复现中按这三类分别统计成功率，能快速定位瓶颈，比只看一个总分有用得多。

应当自建但官方未给的指标

  1. 平均交互步数：达到充分证据平均需要几步。这直接决定系统在真实场景的可用性——交互是要花时间的。
  2. 交互的信息增益分布：统计每一步 $I(Y; F_i \mid E_t)$ 的实际分布，看模型是否真的在选信息量最大的交互，还是在学习数据里的频率偏置。
  3. 证据充分性判断的校准度：声称「充分」时实际正确的比例。若校准差，阈值需要重新调。
  4. 模态退化检查：各模态被选中的比例。若某个模态长期接近零，说明对齐阶段失败，模型在单模态工作。

局限

  • 6 类原子交互覆盖的物理属性维度有限，真实世界需要更丰富的交互类型；
  • 长链任务的误差累积与失败恢复尚未给出量化分析；
  • 数据集规模（近 2000 物体）相对视觉预训练数据仍然很小——这是所有需要物理采集的数据集的共同约束。

与被动多模态融合的对比

维度 被动融合 ROMA（主动感知）
动作空间 无（只能看已有的） 含交互选择
证据不足时 输出低置信度猜测 主动补一次交互
适用属性 可从外观推断的（颜色、形状） 需交互才能知的（重量、内容物、软硬）
成本 一次推断 多轮交互（耗时）
失败模式 静默答错 交互预算耗尽后报「不确定」

关键差异在失败模式：被动融合会静默答错，主动感知会明确报「不确定」。在物理系统上，后者安全得多——错误的确定答案可能导致机器人做出危险动作。

与 VLA 的关系：正交而非替代

  • VLA 解决：理解了之后怎么动；
  • ROMA 解决：理解不足时怎么补。

两者可以串联：ROMA 先问清物体的物理属性，VLA 再据此执行操作。真正的主动具身 Agent 需要两者都具备。

这也解释了为什么 ROMA 把自己定位为「为下一代主动具身 Agent 铺路」——它是能力拼图中的一块，不是完整方案。

与具身问答（EQA）类工作的关系

embodied QA 方向也研究「为回答问题去探索环境」，但通常聚焦空间探索（走到另一个房间去看），而 ROMA 聚焦物理属性探测（摇一摇听声音）。前者改变的是观察视角，后者改变的是物体状态。两者可以结合：先找到物体在哪，再决定怎么探测它。

与触觉/力觉单一模态工作的关系

触觉与力觉方向有大量关于「用接触推断材质、滑移、硬度」的工作，但多数是单一模态、单一属性的专用模型。ROMA 的增量在于：

  1. 把四个模态放进同一个决策框架；
  2. 让模态选择本身成为可学习的决策；
  3. 提供统一的数据与评测。

这是从「专用感知模型」到「通用感知决策系统」的一步。
