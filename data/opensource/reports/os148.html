一条反主流的路线

机器人学习的标准范式是：收集数据 → 训练策略 → 部署模型。RoboICL 走了另一条路：

  • 冻结 GPT-6 Astra
  • 不训练任务专用 VLA
  • 只在推理时向模型提供少量示范
  • 持续保留「机器人刚刚执行过什么、环境发生了什么」

它要回答的问题

如果不训练模型参数，只给机器人看一段同任务的示范，它能否学会精密插入、长程双臂协作和依赖初始状态的操作？

这个问题之所以有价值，是因为它把「机器人能力」的来源从参数更新转移到了上下文组织——如果成立，就意味着获取新技能的成本从「训练」降到「写一个 prompt」。

为什么这个问题不简单

通用视觉语言模型已经能识别物体、理解自然语言指令，并在开放式操作中展现很强的推理能力。但机器人控制还要求三件事：

  1. 把意图转换成连续动作（不是分类或生成文本）
  2. 根据接触、抓取失败和环境变化不断修正
  3. 长程任务后半段可能需要重新查看最初的目标状态

具体来说：一次看似合理的抓取可能没有夹住物体；一段轨迹可能被控制器提前中断；长程任务走到一半需要回头确认起始状态。这些都需要执行历史参与决策，而这正是普通 VLM 调用所没有的。

核心思路

把示范和机器人自己的执行历史都组织为模型能够读取的具身上下文，让冻结的 GPT-6 Astra 在每次决策时参考这些经验，直接输出下一段双臂动作。

上下文的组织方式

RoboICL 的「上下文」不是一个 prompt 字符串，而是三类信息的结构化组织：

┌────────────────────────────────────────┐
│  任务指令（自然语言）                      │
├────────────────────────────────────────┤
│  示范段（Demonstration）                  │
│  - 同任务的一段人类/遥操作示范              │
│  - 观测序列 + 对应动作序列                  │
├────────────────────────────────────────┤
│  执行历史（Execution History）            │
│  - 机器人刚才执行了什么动作                 │
│  - 环境因此发生了什么变化                   │
├────────────────────────────────────────┤
│  当前观测（Current Observation）          │
└────────────────────────────────────────┘
                    │
                    ▼
        冻结的 GPT-6 Astra
                    │
                    ▼
          下一段双臂动作

为什么「执行历史」这一块最关键

普通 VLM 调用是无状态的：每次给一张图，问一个问题。但机器人操作是强时序的：

场景 需要什么 无状态 VLM 能否处理
抓取失败重试 知道上次是怎么抓的、怎么失败的 否
长程任务进度判断 知道已经完成了哪几步 否
依赖初始状态的操作 记住最开始物体放在哪 否

RoboICL 明确把执行历史组织进上下文，正是为了补上这三块。这对应 RoboDojo 任务分类里的 Memory 与 Long-Horizon 两类。

上下文长度的现实约束

执行历史 + 示范 + 当前观测三者叠加，token 数增长很快。这是这条路线的核心工程挑战：

  • 观测图像 token 化后很占空间
  • 历史越长，单次调用成本越高
  • 但砍掉历史就退化成无状态调用，失去核心优势

实践上需要在历史保留窗口与调用成本之间做取舍，这也是为什么 RoboICL 在 Memory 类任务上的表现特别值得关注。

与微调路线的本质区别

维度 微调 VLA RoboICL
能力来源 参数更新 上下文组织
新任务成本 采集数据 + 训练 提供一段示范
部署灵活性 每任务一套权重 一套权重覆盖多任务
对模型能力依赖 中等 极高（完全依赖基座）

这个对比也揭示了它的风险：能力上限完全由基座模型决定。如果 GPT-6 Astra 在某个物理推理维度上弱，RoboICL 没有任何办法补——因为模型是冻结的。

思想来源

In-Context Learning（ICL）在 NLP 中的成功——不更新参数，只靠上下文里的示例就能让模型完成新任务。RoboICL 把这个思路迁移到具身领域，并针对机器人操作的时序特性做了关键改造：把执行历史也放进上下文。

这个改造是必要的：NLP 的 ICL 处理的通常是单轮输入输出，而机器人操作是多轮、强时序、需要记忆的。

概念性最小示例

以下为结构示意，具体 API 以仓库 README 为准：

from roboicl import RoboICLAgent

agent = RoboICLAgent(
    backbone='gpt-6-astra',      # 冻结，不参与训练
    history_window=20,           # 执行历史保留窗口
)

# 提供一段同任务示范（这是唯一的「任务适配」动作）
demo = load_demo('insert_peg_01')
agent.add_demonstration(demo)

obs = env.reset()
while not done:
    # 每次决策都把示范 + 执行历史一起送进上下文
    action_segment = agent.predict(
        obs=obs,
        instruction='把插销插入孔内',
    )
    obs, done = env.step_segment(action_segment)

关键实践提醒

示范的质量比数量重要。RoboICL 在 RoboDojo 上每类任务只用一段示范。这意味着选哪一段直接决定了效果——优先选：

  • 覆盖完整动作序列的
  • 速度均匀、无冗余动作的
  • 观测视角与部署时一致的

调参优先级

  1. history_window：太小丢掉长程信息，太大撑爆上下文。按任务步数设，通常取任务总步数的 1—2 倍
  2. 观测分辨率：直接影响 token 成本，是省钱的第一杠杆
  3. 示范选择：如上述，质量优先

常见坑

  • 把示范当成 few-shot 随便塞：示范必须是同任务的，跨任务示范会误导
  • 忽略调用成本：长上下文 + 图像 token 的成本增长很快，先在小任务上测成本
  • 期待它替代微调：RoboICL 适合快速验证与低数据量场景，不是微调路线的全面替代

性能解读的注意事项

评测对象 GPT-6 Astra 是一个封闭的商业模型，这带来两个必须承认的限制：

  1. 可复现性受限——模型版本变化会改变结果，他人无法完全复现
  2. 成本不可控——调用费用与速率限制由服务商决定

因此 RoboICL 的结果应被理解为「这条路线的可行性验证」，而不是「一个可以自由部署的方案」。它的价值在于证明了不训练也能做到什么程度，为后续用开源模型复现这条路线提供了参照。

与 VPP2（os145）的可比性

两者都在 RoboDojo 上评测，但路线完全不同：

  • VPP2：训一个专门的 WAM 模型，不使用额外数据
  • RoboICL：不训练，靠冻结大模型 + 上下文

VPP2 在 RoboDojo 榜首（平均成功率 32.26%）。RoboICL 的价值不在于超越它，而在于展示了零训练成本能达到的水位。对数据稀缺、算力有限的团队，这个水位可能已经够用。

怎么选

  • 数据充足、追求上限 → WAM / 微调 VLA
  • 数据稀缺、要快速验证新任务 → RoboICL
  • 不能接受商业 API 依赖 → 排除 RoboICL，或等开源基座上的复现

RoboICL 的核心风险

能力上限完全由基座决定，且无法补救。因为模型冻结，任何基座的能力短板都会直接传导到机器人表现。这与微调路线形成鲜明对比——微调可以用领域数据补短板，RoboICL 不行。

这个风险在数据丰富的成熟任务上不明显，但在基座没见过的物理交互上会暴露。

RoboICL 的核心优势

新任务边际成本极低。从「做一个新任务」的角度看：

  • 微调：采集 + 标注 + 训练，天到周级
  • RoboICL：录一段示范，分钟级

对需要快速覆盖大量长尾任务的场景（例如家庭服务），这个差距是决定性的。

评测透明度的示范意义

929 条可播放的三视角执行记录，是 RoboICL 对整个领域最有价值的贡献之一。它把「报一个成功率」升级为「把每条执行都摊开给人看」。这个做法如果被更多工作采用，会大幅改善机器人评测的可信度。
