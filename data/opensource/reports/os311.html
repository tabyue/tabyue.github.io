Robbyant/lingbot-touch 是蚂蚁灵波（Robbyant）开放的触觉表征仓库，对应论文 Learning Heterogeneous Tactile Representation for General Dexterous Manipulation（arXiv 2611.12806）。仓库 Python、Apache-2.0、2026-11-09 创建、11-11 更新，约 794 star（2026-11-22 核验）。

它要解决的问题很具体：商用触觉传感器在阵列密度（几十到上千 taxel）、信号形式（电阻 / 电容 / 视触觉图像 / 磁力）、安装位置（指尖 / 指腹 / 掌面）上差异极大，同一套编码器换一块传感器就要重训。lingbot-touch 学一套能统一多源触觉输入的异构表征，让下游灵巧操作策略不必为每种硬件单独设计输入头。

收录价值在于：触觉侧的开源多半是单点数据集或单个传感器驱动，把「跨硬件表征」作为独立可复用模块开放的不多。配合站内 /learn/sensors-hardware 的触觉传感器一章（Hertz 接触、视触觉标定、CoP 与滑动判据）可以直接上手，也呼应本轮 p404 LocoMuJoCo 与 os314 HandsOn 对灵巧操作评测的需求。

按仓库定位与论文标题，可归纳为三层（注意：结构性归纳，具体网络结构与训练配置以 README 与论文正文为准）：

  1. 多源输入层：把不同传感器的原始信号（taxel 阵列、视触觉图像、力 / 力矩序列）统一成时间对齐的张量，处理采样率不一致与量纲差异。
  2. 异构表征层：为每类传感器保留专用编码器，再映射到共享潜空间；训练目标通常包含跨模态对齐与时序预测，使同一物理接触在不同硬件上得到相近表示。
  3. 策略接口层：把潜表示作为下游模仿学习 / 强化学习策略的观测输入，替换原本的纯视觉观测或拼接触觉原始值。

这套分层的意义在于把「传感器硬件」与「策略」解耦：换传感器只需重训或替换该分支的编码器，共享潜空间与策略侧不动。对本轮 p402 AFFECT 强调的「什么观测才是真正的新增信息」也是个实际注脚——若触觉变化可由视觉与已执行动作预测，直接拼原始触觉值往往带不来增益，先做表征再谈融合更合理。

  • Learning What Actions Change: Action Effect Matching for Dynamics-Faithful World Models（arXiv 2611.25980，本轮 p402）：说明「观测里哪些变化才是动作造成的新增信息」，是判断触觉输入是否带来增益的评测侧参照。
  • TacInno: Teaching Vision-Language-Action Models the Contact Dynamics Beyond Vision and Action（arXiv 2611.26405）：提出触觉创新（tactile innovation）作为监督信号，与「先做表征再融合」形成有趣对照。

  1. 先读 README 的数据契约：确认支持哪些传感器、输入张量形状与采样率，别拿自己的 CSV 硬套。
  2. 跑通一个预训练编码器的推理：用官方 checkpoint 在示例样本上打印潜向量维度与数值范围，确认加载无误。
  3. 对齐时间戳：触觉、视觉与机器人状态的采样率通常不同，先做时间对齐再谈融合，这是触觉管线最常见的隐性错误。
  4. 做一次「有没有增益」的对照：纯视觉基线 vs 拼接触觉表征，同一策略同一随机种子，别只报加了触觉的版本。
  5. 单独测跨硬件迁移：在 A 传感器上学、在 B 传感器上推理，量化异构表征的实际价值。
  6. 记录传感器元数据：型号、标定参数、安装位置与固件版本一并归档，触觉数据离开这些元数据几乎无法复现。

高频坑：把异构表征当成即插即用的通用插件（它仍需要按硬件做适配）；忽略时间对齐导致触觉与动作错位；用原始触觉值直接与图像 token 拼接造成量纲失衡；只报成功率提升却不做纯视觉对照。
