从「为改变而行动」到「为求知而行动」

现有具身评测分成两半，中间有个明显的空档：

类型 代表 测什么 缺什么
Manipulation 基准 RoboCasa 等 acting to change：把场景改成给定目标状态 目标状态是给定的，不需要「发现」
科学发现基准 各类 agent 基准 knowing：推断未知量 把物理实验替换成符号动作或数值查询

真实世界里这两件事 inseparable。要知道一根线是否带电、泵为什么不启动，Agent 必须先动手交互去取数据。

EmbodiedLab 填的就是这个空档：acting to know。

怎么做到「不可预知但可精确评分」

这是整个基准最关键的设计。选择定量科学实验作为载体：

  • 每个实例重新采样系统参数（比如电阻阻值、溶液浓度），所以 Agent 不可能从训练数据里背出答案；
  • 但实验有确定的物理答案，所以评分是精确的，而不是靠人打分或 LLM 裁判。

这一招同时解决了开放式实验「难以自动评测」与封闭式实验「可以背答案」两个问题。

三级接口：用来定位瓶颈

T0  原生控制
    Agent 拿到：像素 + 关节状态
    Agent 自己写：感知 + 运动规划 + 操作代码

T1  + 特权感知
    额外提供：真值深度 + 无碰撞运动规划
    剥离掉：感知与规划的难度

T2  + 蒸馏技能
    额外提供：grasp / place / press 等基础技能库
    剥离掉：底层操作执行难度

同一个模型在 T0 / T1 / T2 上的分数差，直接告诉你是哪一层拖了后腿：

  • T1 比 T0 高很多 → 瓶颈在感知与规划；
  • T2 比 T1 高很多 → 瓶颈在底层操作执行；
  • 三级都不高 → 瓶颈在任务理解与实验设计本身。

这个诊断设计是 EmbodiedLab 比起「给一个总分」的基准最实用的部分。

评分三件套

一次实验被判成功需要同时满足：

  1. 提交正确数值答案，在容差内；
  2. 给出仪器读数作为证据（读数是 episode 中真实记录的，不是事后编的）；
  3. 把实验台恢复原状（关掉加热器、把工具放回去）。

第 3 条特别值得注意：它把「执行不留烂摊子」变成了硬指标，而这恰恰是很多具身系统评测里被忽略、但在真实部署中很致命的能力。

失败分布比总分更有信息

论文的关键发现是：对每一个 Agent，多数失败发生在与实验台的交互环节，而不是抽象推理环节。典型故障：

  • 抓取滑脱；
  • 仪表数字看错一位；
  • 台面没恢复原状导致后续步骤失效。

也就是说：假设常常是对的，手常常是笨的。

技能 vs 感知，谁更值钱

操作技能（T2）对弱 Agent 的帮助大于感知与运动规划（T1）。这个结论对资源分配有直接指导意义：弱模型缺的首先是可靠的底层操作原语，与其继续堆感知模块，不如先给它一套能用的 grasp / place / press。

这个基准适合谁

  • 做具身 Agent 分层设计的团队：T0/T1/T2 是现成的瓶颈诊断工具。
  • 做科学发现 Agent 的团队：把符号实验拉回物理交互，检验「会不会真的动手」。
  • 做长程执行的团队：台面复位这条硬指标可以借用到自己的评测里。

高频坑

  • 直接看总分：一定要分层看，T0 与 T2 的差值才是信息所在。
  • 忽略证据读数要求：Agent 猜对答案但没有记录读数，仍然判失败。这一点在做自己的实验类评测时非常值得抄。
  • 把仿真结果外推到真实实验室：论文自己也声明了这是受控设置。
