核心主张：机器人代码要能长期演化，必须先能被精确归因。

Code-as-Policies / Voyager 一类工作证明了「让大模型写机器人动作代码」的泛化能力，但它们共享一个致命弱点——代码库是扁平的。失败发生时，系统只能看到「某处出错了」，无法定位到具体是哪个技能分支的责任，于是最省事的修复方式就是全局重写，而这恰恰会破坏已经正确的部分。

RoboRSI 的第一步是给能力分层：底层 Base Skills（运动学、点云滤波）、中层 Atomic Skills（表面对齐、夹爪开合）、顶层 Compound Skills（房间整理、货架分拣）。每一层都有显式的 I/O 契约与后置条件断言。

为什么契约这么关键：有了契约，一次执行异常可以被严格归因到责任分支——是输入不满足前置条件，还是输出违反后置条件，还是调度顺序错。归因精度做到了 95.8%，而准确归因正是「只改该改的地方」的前提，也是避免灾难性遗忘的机制性保障。

第二步是治理流程：单个大模型既写规划又写代码又做评审，等于自己给自己改卷。RoboRSI 拆成四个角色——Manager 算 token/执行预算并排发布里程碑，Planner 把高层意图编译成技能调用 DAG，Engineer 只合成局限在失败子分支内的模块化外科补丁，Reviewer 在仿真沙箱里跑回归套件、确认零退化才合入主库。

第三步是资产沉淀：频繁共现的稳定原子调用序列会被自动冻结并编译成可复用的复合原语，技能库随任务累积自我增强。真机 104 轮自主整理沉淀出 32 个已验证技能，正是这条机制在起作用。

契约检查示意

'''
技能契约：前置条件 + 后置条件断言，用于精确归因
'''
class SkillContract:
    def __init__(self, name, pre, post):
        self.name, self.pre, self.post = name, pre, post

    def check(self, state_in, state_out):
        if not self.pre(state_in):
            return 'PRECONDITION_VIOLATED'
        if not self.post(state_out):
            return 'POSTCONDITION_VIOLATED'
        return 'OK'

排错要点

  • 归因精度上不去：契约写得太宽松，后置条件只检查了「不报错」而非「状态真的改变了」
  • Engineer 补丁越改越大：DAG 切分粒度太粗，一个节点承担了过多职责
  • 长期运行出现退化：Reviewer 的回归套件覆盖不足，需补失败样本的回归用例
  • 技能库膨胀但不复用：固化阈值 $\theta$ 太低，把偶发共现也冻结了

读表要点：RoboRSI 与 COAP 同属「代码即策略」路线，但分工不同——COAP 强调测试时不跑模型（状态估计 + 代码决策），RoboRSI 强调多智能体治理下的长期演化。两者都把「可验证」放在首位，这与纯神经网络路线的哲学根本不同。
