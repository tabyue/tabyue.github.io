项目概述

RoboParty RP1 是在 IROS 2026（9/27—10/2，匹兹堡）上发布的全栈开源人形机器人平台，建立在 RoboParty 早前的 ROBOTO_ORIGIN（RPO） 之上。

分层开放路线：机械设计 → 执行器模组 → 运动控制系统 → 仿真环境 → SDK → 训练工具。开源范围从软件层延伸到整个机器人技术栈。

PartyOS 与 UFO 框架

UFO 框架是这份发布里最有辨识度的部分：用无监督强化学习训练低层运动策略，覆盖三类行为：

  • 技能切换（skill transitions）
  • 扰动恢复（disturbance recovery）
  • 跌倒恢复（fall recovery）

关键词是「无监督」——不依赖人工设计的奖励或分阶段课程，而是让策略自己 discover 出可用的低层行为库。

设计意图：让开发者能横跨机器人控制与 AI 训练两层工作，而不是把物理本体和软件当成两套系统分开处理。这直接对准了当前人形研究的一个现实痛点——做控制的和做学习的往往是两拨人，中间的接口层没人负责。

IROS 现场演示：「Kick Me」测试——观众可以 physically 推机器人，观察它调整姿态并恢复平衡。这个演示选得很聪明：它把控制算法的能力测试变成了任何人都能参与的交互。

能力与边界

已开放：

  • RPO：硬件设计、ROS 2 软件、RL 训练流程、URDF/MJCF、固件、导航、XR 遥操作
  • RP1：通过 PartyOS / UFO 逐步开放整机栈
  • IROS 现场验证了扰动恢复能力（Kick Me 测试）

边界与风险：

  1. RP1 是渐进式开放，当前可获取的内容少于 RPO；别假设「现在就能拿到全套图纸」
  2. 160 Nm 峰值扭矩的整机需要相应的安全设施与操作规范
  3. GPLv3 许可对商业衍生品有传染性，与 Apache-2.0 项目（如 os136 / os138）的合规路径完全不同
  4. 「5000 人社区」是公司自报数字，第三方活跃度需自行判断
  5. 硬件物料与加工成本未公开，实际入手门槛可能高于纯软件项目

与同类开源人形平台对比

平台 开放层 许可 适合谁
RoboParty RP1 / RPO 整机硬件 + 控制 + 训练工具 GPLv3 要一台能改的人形的高校 / 创客
宇树 UnifoLM-WLA-1.0（os136） 模型权重 + 训练代码 + 数据集 Apache-2.0 已有 G1，想换模型
智元 sonic_for_a3（os138） 全身控制 + sim2sim + 边缘部署 Apache-2.0 研究 WBC 算法
宇树 H2 / G1 本体 商品硬件 + 部分 SDK 各自许可 要现货本体

核心差异是开放层而非开放度。三者的开放层不同：模型 / 控制栈 / 整机。对高校团队来说这是真正的可选项——你可以只要模型（宇树）、只要控制（智元）、或连本体一起自己造（RoboParty）。

选型建议：预算有限且想深入理解整机 → RPO 的设计文件 + ROS 2 软件是最好的教材；想要快速出成果 → 直接用宇树 / 智元的现成栈。
