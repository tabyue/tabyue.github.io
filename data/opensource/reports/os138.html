项目概述

AgibotTech/sonic_for_a3 是智元机器人 2026 年 9 月 24 日发布的开源仓库，把 NVIDIA GEAR 的 SONIC 全身控制（whole-body control）工作流适配到 A3 人形机器人。

这是一个训练到部署全链路的发布，不是单点算法：

环节 内容
训练 Hydra 配置、launcher、URDF/MJCF 资产、CSV 示例、reward/observation 契约
仿真验证 MuJoCo sim2sim，含闭环踝 / 腰关节求解器
边缘部署 C++ 高性能推理：A3 板载 RK3588S 走 RKNN；A3 Ultra 走 Drive Thor
权重 Hugging Face step-200,000 checkpoint（035），覆盖基础行走与简单操作
许可 Apache-2.0（A3 机器人描述派生自 AgibotTech/A3-A3U-robot-model，Mulan PSL v2）

为什么重要：这是少见的把全尺寸人形的完整控制栈（训练 → sim2sim → 边缘 NPU 部署）以 Apache-2.0 全部公开的项目。此前开发者要碰这一层，基本必须有自家硬件。

训练 → 部署链路

Hydra configs + launchers + URDF/MJCF
        ↓
  强化学习训练（reward / observation 契约开放）
        ↓
  MuJoCo sim2sim（闭环踝 / 腰关节求解器）
        ↓
  域随机化（同时覆盖 A3 与 A3 Ultra）
        ↓
  C++ 部署：RK3588S (RKNN)  |  A3 Ultra (Drive Thor)

sim2sim 环节是这份发布里工程含量最高的部分：MuJoCo 里做闭环的踝关节与腰关节求解，而不是简单地把训练环境的观测搬过去。

部署环节双路径设计很有针对性：

  • RK3588S（RKNN）：瑞芯微 NPU，低成本边缘推理，对应 A3 标准版板载算力
  • Drive Thor：NVIDIA 高算力平台，对应 A3 Ultra

文档化的 sim-to-real 约束包括 T–N 电机曲线（力矩-转速特性）与被动足部仿真——后者用近似鞋底柔性的方式抑制踮脚行为，但可能引入不稳定。这类细节通常是团队踩坑后才写进文档的，公开发布里很少见。

快速上手

git clone https://github.com/AgibotTech/sonic_for_a3
# 按仓库 README 安装依赖（Python 侧训练 + C++ 侧部署工具链）
# 训练：Hydra 配置驱动
python train.py --config-name=a3_sonic
# sim2sim 验证
python sim2sim.py --checkpoint ckpt/035

权重：Hugging Face 上的 step-200,000 checkpoint（035），在内部动作数据集上训练，覆盖基础行走与简单操作。

已知限制（仓库明确列出）：

  • 缺少 SMPL 与遥操作编码器 → 上游需要自备 retargeting 模块
  • 腕部跟踪较差
  • 不支持跪姿等地面接触动作
  • checkpoint 使用 G1 编码器，20 ms 帧间隔、180 ms 未来帧曝光

安全提醒（务必遵守）：仓库强烈建议在真实机器人遥操作前使用安全龙门，并先在仿真中完成验证。这不是套话——全身控制的失败模式是整机倾倒。

能力与边界

已覆盖：

  • 基础行走与简单操作（step-200,000 checkpoint）
  • A3 与 A3 Ultra 双硬件的域随机化，支持跨硬件部署
  • 从训练配置到边缘 NPU 推理的完整链路

未覆盖 / 已知缺陷：

  1. 无 SMPL / 遥操作编码器 → 需要上游 retargeting
  2. 腕部跟踪质量差，精细操作受限
  3. 不支持地面接触动作（跪姿等）
  4. 被动足部仿真近似鞋底柔性，可能引入不稳定
  5. checkpoint 的真实机器人表现与仿真是否一致，仓库未提供对比数据

待观察的信号：更好的腕部跟踪 checkpoint、SMPL 与遥操作编码器发布、开源遥操作管线、A3 Ultra 的 Thor 部署教程。
