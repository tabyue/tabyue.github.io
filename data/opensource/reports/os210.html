为什么需要潜动作接口

VLA 的预训练数据是瓶颈中的瓶颈。带动作标签的机器人示教昂贵且覆盖面窄，而人类视频与网络视频虽然覆盖广，却没有对应的机器人指令。更麻烦的是不同本体的控制空间互不兼容：

本体 动作维度 坐标系 语义
单臂 6-DoF 7（6 关节 + 夹爪） 基座坐标系 关节角 / 末端位姿
双臂移动操作 20+ 底盘 + 双臂 含底盘速度与躯干高度
灵巧手 20+ 每手 手部坐标系 手指关节 / 肌腱驱动

这三类数据无法直接池在同一个「预测原生动作」的目标下。

潜动作（latent action）提供的是一个中间接口：它编码的是「观测之间发生了什么变化」，不依赖任何具体本体的控制定义。先在潜动作空间上做大规模预训练，再用少量本体数据把潜动作映射到该本体的实际动作，就把「数据规模」与「本体兼容」解耦了。

三个让潜动作不塌方的设计

  1. 残差未来特征预测：预测未来特征相对当前的残差，而不是绝对特征。绝对预测会让模型倾向于记住场景外观（「厨房大概长这样」），残差则迫使它关注变化量。
  2. 相机补偿的 3D 流监督：用相机运动补偿后的三维流做监督。不补偿的话，第一人称视频里相机一动，像素全变，模型会以为「世界发生了大变化」。
  3. 相机运动解耦：显式把 ego-motion 与场景变化分离。这一条与第 2 条配合，是这类方法能否 work 的分水岭。

两阶段数据流

阶段一：RynnLAM（学潜动作，与本体无关）
    视频帧序列 {o_t, o_t+1, ...}
        -> 视觉编码器
        -> 残差未来特征预测头
        -> 相机补偿 3D 流监督 + 相机运动解耦
        -> 连续潜动作 z_t

阶段二：RynnVLA-Latent（学策略，再适配本体）
    (观测 o_t, 语言指令 l)
        -> 预训练主干
        -> 流匹配预测潜动作块 z_t:t+H
        -> 动作专家适配到具体本体动作 a_t:t+H

关键点在于阶段一完全不需要机器人动作标签，所以人类视频这种「量大但没有控制指令」的数据能被真正利用起来。

为什么用流匹配而不是自回归

潜动作是连续向量，用离散 token 自回归会引入量化损失；流匹配直接在连续空间建模分布，且天生支持一次预测一个动作块（chunk），与 VLA 里通行的 action chunk 执行方式一致。

最小推理骨架

import torch
from rynnvla_latent import RynnVLALatent, load_processor

processor = load_processor("rynnvla-latent-4b")
policy = RynnVLALatent.from_pretrained("rynnvla-latent-4b").cuda().eval()

batch = processor(
    images=[obs["head"], obs["wrist"]],
    instruction="pick up the red cup and place it on the plate",
).to("cuda")

with torch.no_grad():
    # 先出潜动作块，再由动作专家映射到本体动作空间
    latent_chunk = policy.predict_latent_chunk(batch)   # [1, H, D_latent]
    actions = policy.action_expert.decode(
        latent_chunk, embodiment="single_arm_7dof"
    )                                                   # [1, H, D_action]

robot.execute(actions[0, :h].cpu().numpy())   # 滚动视界：只执行前 h 步

接入自己的本体

  1. 用自有示教数据（几十到几百条即可）微调 action_expert，主干保持冻结；
  2. 定义本体的 embodiment 描述（关节数、坐标系、动作语义）；
  3. 在目标基准或真机上跑滚动视界评测，先扫 H 与 h 的组合再谈调参。

  • LIBERO-Plus 的 84.7% 标注了「无基准特化适配」，这是这组数字里最有价值的一个限定——它说明分数来自通用预训练而非测试时针对性调整。

选型建议

  • 手上几乎没有带标签示教、但有大量人类视频：潜动作路线是最直接的资产化方案。
  • 已有大量高质量本体示教：先跑论文的数据规模曲线判断边际收益，潜动作预训练的增益可能在数据量足够后迅速饱和。
  • 多本体并存：把预训练与本体适配解耦，是这个路线相对「每个本体训一个 VLA」最大的工程价值。

高频坑

  • ego-motion 污染：用第一人称数据但没有做相机运动解耦，潜动作会退化成「相机怎么动」。验证方法是把相机固定后再看潜动作是否还有信息量。
  • 把 LIBERO 分数当成通用能力：98.8% 已接近饱和，区分度很低。要看差异请用 LIBERO-Plus 或 VLABench。
  • 动作专家微调过拟合：本体适配阶段数据少，容易把主干的通用能力覆盖掉。建议冻结主干、只训动作专家。
