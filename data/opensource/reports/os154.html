BiGym 2.0 要解决什么

人形家务操作和机械臂操作是两个难度层级完全不同的问题。

机械臂操作时基座固定，你只需要考虑末端去哪、抓什么、怎么避开障碍。而人形机器人做家务时，手臂在干活，身体同时在平衡、迈步、改变姿态。这意味着：

  • 手臂的运动会反作用于躯干，改变整体质心与支撑多边形
  • 为了够到高处的柜子要踮脚或迈步，为了拿地上的东西要弯腰或下蹲——操作任务本身就隐含着运动规划
  • 控制器必须在「保持不倒」和「完成操作」两个目标之间持续权衡

BiGym 2.0 就是为这个问题设计的基准：它是 BiGym 面向 Unitree G1 人形机器人 的重构版本，覆盖 20 项家务任务，并且——这一点很关键——示教与评测统一使用同一个全身控制器。

为什么「统一全身控制器」是核心设计

在人形操作基准里，如果不同方法各用各的控制器，那么最终分数的差异可能来自控制器，而非被测方法。BiGym 2.0 的做法是：所有方法共享同一套机载视角、同一套本体感受、同一个全身控制器。

这使得对比变成 控制变量实验：差异只能来自被测策略本身。

数据规模

  • 20 项家务任务
  • 每项任务 60 条人类 VR 示教
  • 每条示教带 同步多相机视角 与 全身执行记录

VR 示教的价值在于：它记录的不只是末端轨迹，而是 整个人在执行任务时的全身运动——包括为了达到目标而做的迈步、弯腰、重心转移。这些恰恰是人形操作区别于固定基座操作的精华部分，也是遥操作（只给末端位姿）无法提供的数据。

四类被测方法

BiGym 2.0 同时评测四条技术路线：

  1. VLA 微调——在预训练视觉-语言-动作模型上微调
  2. 模仿学习——直接从示教学习
  3. 示教驱动强化学习——以示教为起点的强化学习
  4. 冷启动编码智能体——给智能体与在线 RL 相同的交互预算，让它直接写程序完成任务

第 4 类是这个基准最有意思的设计。它把「用大模型写机器人程序」这条新兴路线放进了与传统方法同台竞技的位置，而且约束了交互预算以保证公平。

全身控制器的角色

全身控制器处在策略与电机之间，负责把策略输出的高层意图（末端位姿、目标关节构型）转化为满足平衡约束的全身关节指令。

数学上，这是一个带约束的优化问题。设关节角为 $q$，任务目标为末端位姿 $x_d$，则典型形式为：

$$\min_q \ |x_{EE}(q) - x_d|^2_{W_{task}} + \lambda|q - q_{ref}|^2$$

$$\text{s.t.}\quad \text{CoM} \in \text{支撑多边形},\quad \tau_{min} \le \tau \le \tau_{max}$$

第一项是任务跟踪，第二项是构型正则（避免奇异位形），约束是 平衡约束（质心必须落在支撑多边形内）与 力矩限幅。

BiGym 2.0 统一了这一层，意味着被测策略只需要输出「想让手去哪」，不必各自实现平衡控制——这大幅降低了方法间的实现差异，但也意味着基准 不评测 全身控制本身的质量。

冷启动编码智能体的评测设计

「冷启动」的含义是：智能体从零开始，只通过有限的交互来理解和完成任务，而不是先看过示教。

交互预算与在线 RL 对齐，这一点至关重要。否则编码智能体可以无限次试错，公平性就不成立。

这类方法的输出是 程序代码 而非神经网络权重——它调用已有的技能模块（导航、抓取、放置）组成一个执行流程。因此它的优势与劣势都很鲜明：

  • 优势：可解释、可调试、失败后容易定位与修复；对长程任务的结构化分解能力强
  • 劣势：无法处理需要精细力控或连续自适应的环节；依赖底层技能库的质量

实验证实了这一点：编码智能体在九项任务均值上 超过了所有示教驱动 RL 基线，并在 双手够取（bimanual reaching） 上领先——这类任务结构清晰、可分解为「左手去 A、右手去 B」。

第一步：跑通一个环境

先不要碰训练，先确认能渲染并采集一条轨迹：

'''
加载一个 BiGym 2.0 任务并检查观测空间
'''
from bigym.envs import BiGymEnv   # 以仓库实际 API 为准

env = BiGymEnv(task="reach_target", whole_body_controller="default")
obs = env.reset()

print("观测键:", sorted(obs.keys()))
print("相机:", [k for k in obs if "image" in k or "rgb" in k])
print("本体感受维度:", obs.get("proprio", None) and obs["proprio"].shape)

for _ in range(50):
    obs, r, done, info = env.step(env.action_space.sample())
    if done:
        obs = env.reset()

重点检查两件事：相机视角是不是「机载」的（不能有上帝视角，否则评测失真），以及 本体感受是否包含全身关节状态（而不只是手臂）。

读取某任务的 VR 人类示教并检查其完整性
'''
from bigym.data import load_demos

demos = load_demos(task="reach_target", split="train")
print("示教条数:", len(demos))            # 应为 60

d = demos[0]
print("步数:", len(d["actions"]))
print("全身关节维度:", d["qpos"].shape[-1])
print("相机路数:", len(d["images"]))

# 检查示教中是否存在「明显不是操作」的全身运动（迈步/弯腰）
import numpy as np
base_motion = np.abs(np.diff(d["root_pos"], axis=0)).sum(axis=1)
print("root 位移总量:", base_motion.sum())
print("发生显著位移的步占比:", (base_motion > 0.01).mean())

最后一项检查很有用：如果某任务的示教中 root 位移几乎为零，说明这个任务其实不需要全身移动，那么它作为「人形家务」任务的代表性就有限。

明确未解决的开放问题

BiGym 2.0 的作者很诚实地列出了难点，这比单纯报一个总均分更有价值：

  1. 跨工作空间堆叠（cross-workspace stacking）——仍未解决。物体不在同一个可达区域内时，机器人需要移动身体再重新定位，误差累积严重
  2. π0.5 在 pick-box 上表现偏低——说明即使是当前最强的通用 VLA，在特定人形操作任务上仍有明显短板
  3. 多物体运输——对模仿学习、示教驱动 RL、编码智能体 都很难。这类任务要求持续维持多个物体的稳定抓取，同时移动身体

如何解读这些数字

最重要的一点是：编码智能体击败了示教驱动 RL。这在方法论层面是个值得注意的信号。

原因是结构性的：RL 需要在连续动作空间里搜索，而家务任务往往是「离散的技能序列 + 少量连续参数」。编码智能体直接输出程序，天然契合这种结构；RL 则要从零学出这个离散结构，样本效率极低。

反过来说，RL 应该在需要 连续自适应 的任务（如力控插入、柔顺擦拭）上占优——那些恰恰是写程序很难表达的部分。BiGym 2.0 列出的开放问题（跨工作空间堆叠、多物体运输）正是这类需要连续自适应的任务。

作为基准的可信度

BiGym 2.0 在设计上有几个提高可信度的选择：

  • 统一全身控制器 → 消除控制器差异
  • 统一机载视角与本体感受 → 消除感知差异
  • 环境、示教、评测轨迹 全部开源 → 可复现
  • 主动列出未解决任务 → 避免「报喜不报忧」

主要局限是：目前只有 20 项任务，且全部基于 Unitree G1 单一本体，跨本体泛化能力无法通过该基准评估。

与其他基准的本质区别

LIBERO、RoboTwin 这类基准的机器人是 固定基座 的——它们评测的是「给定观察，如何操作」，不涉及平衡与移动。BiGym 2.0 把 全身运动 显式地纳入了评测对象。

这带来一个直接后果：在 LIBERO 上表现好的方法，在 BiGym 2.0 上未必好。因为前者从未面对过「伸手去够时身体会失去平衡」这个问题。这也解释了为什么 π0.5 在 pick-box 上表现偏低——它的训练分布里没有这类全身耦合。

使用建议

  • 评估通用 VLA 的操作能力 → LIBERO / LIBERO-Pro（生态成熟、对比充分）
  • 评估人形全身操作 → BiGym 2.0
  • 评估跨本体、仿真+真机综合能力 → RoboDojo
  • 评估长时程任务与记忆 → HomeBody

如果你正在做人形操作方向，建议 同时 跑 LIBERO 与 BiGym 2.0：两者的分数差恰好量化了「全身耦合」带来的额外难度。
