## 本次新踩到的坑

- **候选开源大量已收录**：本轮 WebSearch 找到的 RoboParty RP1、OpenWAM、RoboRSI、EmbodiedEvo、
  DexForce/UNITAS 全部已在库。解决办法是改用 **GitHub Search API**
  （`topic:embodied-ai / robot-learning / humanoid / vision-language-action` + `pushed:>2026-10-05`）
  批量拉取后与现有 `gh` URL 清单做比对，一次拿到 4 个真正的新仓库。
- **`gh api "search/repositories?...&per_page=30"` 在 PowerShell 里被拆成 13 个参数**报错
  `accepts 1 arg(s), received 13`（& 与空格被解析）。改写成 `.py` 文件用 urllib 调 API 即可；
  PowerShell 侧不要内联带 `&` 的 URL。
- **`ConvertFrom-Json` 处理 search API 大响应会崩**（`传入的对象无效，应为":"或"}"`），
  用 `gh api ... --jq` 或在 Python 里解析更稳。
- **`python -c "..."` 含非 GBK 字符会 `UnicodeEncodeError`**：诊断脚本必须设
  `$env:PYTHONIOENCODING='utf-8'`，或直接写成 .py 文件。
- **arXiv export API 会返回 429**：改用 `WebFetch https://arxiv.org/abs/<id>` 取标题/作者/日期/摘要更稳。
- **jobs.json 里有条目没有 `url` 键**：查重写 `x['url'] == ...` 会 `KeyError`，必须 `x.get('url','')`。
- **learning-path 的模块名与 learn/*.json 的 name 并不总是一致**：32 个模块里有 3 个对不上——
  `platform-engineering`(具身智能平台工程) → LP 里叫「MLOps与持续交付」；
  `cloud-edge-collaboration`(云边协同) → 「云边端协同架构」；
  `embodied-agent`(具身Agent系统) → 「具身Agent实战项目」。
  按 name 精确匹配会静默漏掉，需按别名处理。
- **一次性写不满 8K 就二次追加**：本次初版只有 4.1K/4.4K，再写 `_upd_learn2.py`
  用「按 shortTitle 找章节 + 章节内标记串（如 `### 八、`）判重 + 追加」补到 6.2K/6.8K，幂等安全。
